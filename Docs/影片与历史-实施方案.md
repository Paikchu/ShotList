# 影片与历史 · 实施方案

更新日期：2026-09-16
分支建议：`feature/film-library`
对应需求：标题支持 / 重制 / 历史改下拉 / 历史找回

---

## 0. 一句话结论

这四条需求表面是四个 UI 改动，实际是同一件事：**给 app 补上「影片」这一层数据实体**。

当前 `ShotStore.shots` 是**一份全局分镜清单**，`HistoryView` 只是它的日期切片视图——日期背后没有实体，所以「重制」无处归档、「历史」没有可切换的对象。一旦 `Film` 立起来：

- 需求 2「重制」与「新建影片」在数据上是同一个动作；
- 需求 4「历史找回」不再是复制数据，而是**切换指针**；
- 需求 3 的数据轴从「日期」换成「影片」，下拉项天然能带标题与更新时间。

反过来说，如果当成四个独立 UI 需求做（标题塞进某个全局字段、历史仍是日期轴、找回靠把旧分镜复制回来），四条会互相打架，且需求 4 必然出现「原片与副本分叉」。

## 2. 数据模型

### 2.1 新增类型（`ShotList/Models/Film.swift`）

```swift
/// 一部影片 = 一次创作。跨天续拍属于同一部影片。
nonisolated struct Film: Identifiable, Codable, Hashable {
    var id: UUID
    /// 影片标题，可为空；空时界面显示「未命名影片」
    var title: String
    /// 这部影片的分镜，编号在影片内从 1 连续
    var shots: [Shot]
    var createdAt: Date
    /// 最后一次内容变更时间（增删改镜头、增删片段、改标题）
    var updatedAt: Date
}

/// 落盘结构：影片库 + 当前指针
nonisolated struct FilmLibrary: Codable {
    var films: [Film]
    var currentFilmID: UUID?
}
```

`Shot` 与 `ShotClip` **结构不变**，不引入嵌套层级变化——这样 `normalize()`、`syncClipFileNames()`、导出、`ShotCardView` 全部不用动。

### 2.2 派生属性（`Film`）

| 属性 | 口径 | 用途 |
|---|---|---|
| `paddedTitle` | 标题 trim 后为空 → 「未命名影片」 | 影片条、下拉项、导出包名 |
| `recordedCount` | `shots` 中至少有一段片段在**磁盘上**的镜头数 | 影片条进度、下拉副行 |
| `isStarted` | `!shots.isEmpty` | 三态判定 |
| `statusText` | 未开始 / 拍摄中 2/5 / 已拍完 5/5 | 下拉项、影片库行 |

### 2.3 存储布局

| 文件 | 现在 | 改造后 |
|---|---|---|
| 元数据 | `Application Support/ShotList/shots.json`（`[Shot]`） | `films.json`（`FilmLibrary`） |
| 删除补偿日志 | `pending-deletions.json`（`[Shot]`） | `pending-deletions.json`（`FilmLibrary`） |
| 片段目录 | `Documents/分镜视频/` 扁平 | **保持扁平**（见下方「为什么不拆目录」） |

### 2.4 迁移方案（P0 的关键路径）

顺序**必须先恢复、后迁移**，否则旧的删除补偿日志会在格式切换后无法解读：

```
load()
 ├─ 1. 若 films.json 存在 → 解码 FilmLibrary，走新路径
 ├─ 2. 否则若 shots.json 存在 → 迁移：
 │      a. 先用旧的 loadShots()（含 recoverPendingDeletions()）得到 [Shot]
 │      b. 包成一部 Film（title = ""，createdAt / updatedAt = 文件的修改时间）
 │      c. 写 films.json（原子写）
 │      d. 成功后把 shots.json 改名 shots.json.migrated（不删除）
 ├─ 3. 两者都不存在 → 按现有「首次启动」判据（目录确实为空）→ 懒建一部空白影片
 └─ 4. 解码失败 → 现有 loadError 路径不变（暂停编辑与清理，绝不覆盖）
```

**回滚保险**：`shots.json.migrated` 一直留在磁盘上，不参与任何读写。若 `films.json` 事后损坏，用户手动改回名字即可退回旧版本能读的状态。开发期同时保留这一行为，便于回归验证。

**懒建影片**：`films` 为空时自动创建一部空白影片并落盘，保证 `currentFilm` 永不为 `nil`，省掉一大片可选值判断。回收空影片时永远保留至少一部。

**为什么不拆 `分镜视频/<影片>/` 目录**（修正上一轮建议）：

拆目录的收益只是「文件」App 里看着清爽，代价却很高——`syncClipFileNames()` 把「编号即位置」这条不变量从**影片内**延长到了**文件系统层**，迁移时要移动全量视频文件，任何中断都会留下半迁移状态，而重建映射需要新的补偿日志。

而真实的冲突风险其实不存在：文件名带秒级时间戳，`makeClipFileName()` 与 `syncClipFileNames()` 都有 attempt 去重循环，跨影片重名会被自动改成 `-2` 后缀，**不会覆盖**。且 `token(from:)` 保留后缀，后续重编号也稳定。

结论：**P0–P3 保持扁平目录**，把它作为独立的可选优化（P4，见 §6.5），不与本次改动耦合。

## 3. `ShotStore` 改造

### 3.1 对外接口保持不变（这是让改动收敛的关键）

```swift
@Published private(set) var films: [Film] = []
@Published private(set) var currentFilmID: UUID?

/// 当前影片的分镜。**只读**对外接口，签名与改造前一致。
///
/// 视图层（ShotListView / HistoryView / ExportView / RootTabView）读到的
/// 仍是 [Shot]，因此这些文件在 P0 阶段几乎不用改。
var shots: [Shot] { currentFilm?.shots ?? [] }
```

发布语义：视图重绘由 `films` / `currentFilmID` 的 `@Published` 驱动；`shots` 是计算属性，body 重算时重新求值，拿到新数据。`ExportView` 里的 `.onChange(of: store.shots)` 也照常工作（`Shot` 是 `Equatable`）。

### 3.2 内部写入改为显式路径

`shots` 对外只读，**内部所有写入**走：

```swift
private var currentIndex: Int? { films.firstIndex { $0.id == currentFilmID } }

/// 用户编辑引起的写入：同时把 updatedAt 推到当前时间
private func mutateCurrentFilm(_ body: (inout Film) -> Void) {
    guard let index = currentIndex else { return }
    body(&films[index])
    films[index].updatedAt = Date()
}

/// 自动校正引起的写入：**不动 updatedAt**（用户没编辑，时间不该跳）
private func repairCurrentFilm(_ body: (inout Film) -> Void) { … }
```

约 30 处 `shots[…] = …` / `shots.append(…)` 机械替换为 `mutateCurrentFilm { $0.shots… }`。区分 mutate / repair 是必要的：`reconcileClipsWithDisk()` 是磁盘自愈，不该把「影片最后更新时间」刷新成现在，否则影片库的排序会莫名其妙地跳。

### 3.3 跨影片边界（**本次最高风险点**）

以下方法原先是「全局一份清单」的写法，改造后必须**限定在当前影片**，逐个核对：

| 方法 | 改造 | 不改的后果 |
|---|---|---|
| `normalize()` | 只重编号当前影片的镜头 | 切到影片 B 会把 A 的编号也重排 |
| `syncClipFileNames()` | 只扫当前影片的 clips | **改名会穿透到别的影片** |
| `applySnapshot()` 的 `used` 集合 | `films.flatMap { $0.shots.flatMap(\.clips) }` | ⚠️ **切到影片 B 时，A 的文件会被判为孤儿** —— 用户点一次「清理未使用的文件」就永久删掉 A 的全部素材。这是不可逆数据丢失，P0 必须在测试里钉死 |
| `nextNumber` | 当前影片内 `max + 1` | 第二部影片的镜头从 6 开始 |
| `recoverPendingDeletions()` | 按影片 id 定位恢复目标 | 恢复的片段插错影片 |
| `deleteEverything()` | 语义改为「删除当前影片」（见 §4.3） | 点「清空」会连别的影片一起删 |

### 3.4 新增成员

```swift
var currentFilm: Film? { … }
var sortedFilms: [Film] { films.sorted { $0.updatedAt > $1.updatedAt } }

func createFilm(title: String = "") -> Film?        // 新建空白影片并切过去
func loadFilm(_ id: Film.ID)                        // 切换当前影片（原片原样留库）
func renameFilm(_ id: Film.ID, to title: String)    // 改标题
func remakeCurrentFilm(title: String = "") -> Film? // 归档旧片 + 新建空白片
func deleteFilm(_ id: Film.ID)                      // 删影片（含片段）
private func discardEmptyCurrentFilm()              // 空影片静默回收（至少留一部）
```

`loadFilm` / `remakeCurrentFilm` 内部先调 `discardEmptyCurrentFilm()`：若当前影片「无镜头 + 标题为空」，静默丢弃。否则影片库会堆积一堆空壳。

## 4. UI 设计

### 4.1 影片条 `FilmBar`（新增 `ShotList/Views/FilmBar.swift`）

分镜页与历史页**复用同一个组件**，不做两套。

```
┌────────────────────────────────────────────┐
│  夏日vlog                            ⌄     │   ← 标题（空时虚线占位）
│  9月14日更新 · 2/5 已拍                     │   ← 副行
└────────────────────────────────────────────┘
```

- 放在 `ShotListView` 的 `List` **之上**，常驻——即使当前影片没有镜头，用户也要能看到标题、能切换影片。
- 左半区整块可点 → 编辑标题；右半区 `chevron.down` → 打开影片菜单。
- 视觉沿用既有语言：`CardContainer` 的圆角与背景、`NotePlaceholder` 的虚线（标题为空时）、`SLDateText` 的相对日期写法。
- 顶部对齐基准要重新校准：影片条插进来后，分镜页首块不再落在 `pageTopInset`，需与历史页、导出页重新对齐（改 `SLSpacing.pageTopInset` 的分镜口径，或给影片条一个专用上边距）。

### 4.2 标题编辑

`alert` + `TextField`（iOS 原生，不叠模态层）：

- 标题：`影片标题`
- 说明：「留空也可以，之后在影片库里按日期找得到。」
- 按钮：取消 / 保存
- 空标题保存 → `title = ""`，界面回落显示「未命名影片」

### 4.3 重制

**「重制」与「新建空白影片」合并为一个动作**，不做两个语义重叠的入口。放在影片菜单里：

```
影片菜单（FilmBar 右侧 ⌄）
──────────────────────────
● 夏日vlog        9月14日 · 2/5      ← 当前项，打勾
  咖啡店探店      9月12日 · 5/5
──────────────────────────
  重制（收起当前影片，开一部空白影片）
```

确认弹层文案（需求 2 的设计重点）——「重制」这个词本身在暗示会丢东西，所以弹层要把「东西去哪了」直接说清楚：

| 元素 | 文案 |
|---|---|
| 标题 | `重制当前影片？` |
| 正文 | `《夏日vlog》会留在影片库里，随时可以载入继续拍。现在打开一部空白影片。` |
| 确认按钮 | `开一部空白影片`（**不写「重制」**） |
| 取消 | `取消` |

正文里的影片名是动态的：未命名时写「当前影片」。

### 4.4 历史页 → 影片库（需求 3）

**移除**：`calendarCard`（`DatePicker(.graphical)`）、`dateHeader`、`dayStepper` / `dayStepButton` / `changeDay`、工具栏的日历展开按钮 `history.calendarToggle`。

**保留**：`progressCard`（口径改为当前影片）、`statRow`、`filterPicker`、`shotList`（卡片列表直连复用）。

**替换为**：顶部同一个 `FilmBar`，下拉即导航器。

筛选简化：日期轴已被影片轴替代，「其他天 / 从未拍」这类跨天分类失去意义，收敛为三档 `全部 | 已拍 | 未拍`。「今天拍了几个」放进进度卡副文案。`Filter` 枚举相应删掉 `otherDays` / `never` / `thatDay`（`ShotStore.recordedShots(on:)` 等按天方法随之删除，标签栏徽标的按天口径也一并改掉）。

空状态：`还没有影片` / 「到分镜页添加第一个镜头，这里会按影片归档每一次拍摄。」

### 4.5 需求 4 的入口

主入口在**分镜页**的影片菜单——选中任一历史影片即完成载入，菜单下方用一句小字给出安全底线：

> 载入不会删除当前影片，它仍留在影片库里。

历史页的「载入继续拍」按钮是同一动作的第二入口（仅当查看的影片不是当前影片时出现）。

### 4.6 三态表达

沿用现有的「图标 + 文字 + 颜色」三重表达，下拉项里直接写文字：

| 状态 | 图标 | 文字 |
|---|---|---|
| 未开始 | `circle.dashed` | 未开始 |
| 拍摄中 | `clock.badge.checkmark` | 2/5 已拍 |
| 已拍完 | `checkmark.circle.fill` | 5/5 已拍完 |

## 5. 导出收敛

导出必须是**当前影片**的导出，否则会把两部 vlog 混进同一时间线。

| 改动 | 位置 |
|---|---|
| `build(shots:clipsDirectory:scope:)` → 增 `filmTitle: String` | `ExportPackageBuilder` |
| 目录/包名带标题：`分镜导出_夏日vlog_20260914`；无标题时退化为 `分镜导出_20260914` | `buildChecked` 的 `folderName` |
| `导出说明.txt` 与 `分镜文字内容指南.md` 增加一行「影片：夏日vlog」 | `writeReadme` / `writeTextGuide` |
| `isCurrent` 判据加 `store.currentFilmID == filmID` | `ExportView.build()` |
| 切换影片时 `export.invalidate()` | `ExportView` 的 `onChange` |
| 「清空所有分镜和视频」（`deleteEverything`）语义改为「删除当前影片」 | `ExportView.maintenanceSection` |
| 概览行「已拍 N / M 个镜头」口径不变，但作用域是当前影片 | `ExportView.overviewSection` |

## 6. 分阶段任务分解

每阶段独立可验收、可提交，不留半完成状态。

### 6.1 P0 · 数据基座（需求 0，不产出可见变化）

**目标**：`Film` 进模型、`films.json` 落盘、老数据无损升级。界面上什么都看不出来，这是刻意的——P0 的验收标准就是「升级前后界面与数据完全一致」。

| 步骤 | 文件 | 要点 |
|---|---|---|
| 1 | `Models/Film.swift`（新） | `Film` / `FilmLibrary` + 派生属性 |
| 2 | `Models/ShotStore.swift` | `films` + `currentFilmID`；`shots` 转只读计算属性；内部写入走 `mutateCurrentFilm` / `repairCurrentFilm`；`committedShots` → `committedFilms`；`writeMetadata()` 写 `FilmLibrary` |
| 3 | `Models/ShotStore.swift` | 迁移逻辑（§2.4）；`load()` 拆成「读 films → 迁 shots → 首次启动」三分支 |
| 4 | `Models/ShotStore.swift` | 按 §3.3 逐项收紧跨影片边界（**孤儿口径是重点**） |
| 5 | `Views/HistoryView.swift` | 按天方法删除后，临时用当前影片口径占位（本阶段不做影片库 UI） |
| 6 | `Views/RootTabView.swift` | 徽标口径改为当前影片待拍数 |
| 7 | `Tools/seed-simulator.py` | 改为写 `films.json`；**演示数据造两部影片**，用于验证跨影片隔离 |
| 8 | `ShotListTests/ShotStoreTests.swift` | 迁移与跨影片隔离用例（§7） |

**验收标准**
- 用改造前的 `shots.json` + 片段目录启动 → 镜头、片段、缩略图、进度与改造前逐项一致；`shots.json.migrated` 存在；`films.json` 内容正确。
- 迁移中途写入失败（用 `IsolatedFileManager` 注入）→ `loadError` 生效、编辑与清理被阻断、`shots.json` 原样。
- 两部影片各有 `镜头01`，切到影片 B 后 `orphanFileNames` **必须为空**；`removeOrphanFiles()` 返回 0。
- `xcodebuild test` 全绿。

## 9. 风险与回滚

| 风险 | 级别 | 处置 |
|---|---|---|
| 孤儿清理跨影片误判 → 素材被永久删除 | **P0** | §3.3 的 `used` 集合必须覆盖全部影片；测试 `testOrphansAreScopedToAllFilms` 钉死；实现前先写这条测试 |
| 迁移中断导致元数据不可读 | **P0** | 原子写 + 保留 `shots.json.migrated`；写失败走现有 `loadError` 阻断路径，绝不覆盖 |
| 切换影片时在途导入/复制写错影片 | P1 | `addClip` 已用 shotID 定位并要求重解析；改造后目标解析要限定在当前影片内，找不到即抛 `targetMissing` |
| UI 顶部对齐基准漂移 | P2 | 影片条插入后重新校准；深色 / 大字号一并截图核对 |
| 影片库随空片堆积膨胀 | P2 | 空影片静默回收，且至少保留一部 |
| `shots` 转计算属性后视图不刷新 | P1 | 所有写入都经 `films` / `currentFilmID`，`@Published` 会发通知；P1 第一步就在模拟器上验证一次切换重绘 |

**回滚**：P0–P3 每阶段一个独立 commit。数据层回滚 = 把 `shots.json.migrated` 改回 `shots.json` 并删除 `films.json`（旧版本即可正常读取）。代码层回滚 = 回退对应 commit。

## 12. 实现纪要（落地后回填，与本文有偏差处以此节为准）

P0–P3 已全部实现，`xcodebuild test` 35 项全绿，模拟器截图见 `Docs/screenshots/影片-0*.png`。落地过程中与本文不一致的地方：

| # | 本文写法 | 实际实现 | 原因 |
|---|---|---|---|
| 1 | §6.4-1 历史页「载入继续拍」按钮（仅非当前影片时出现） | **未做** | 历史页主体就是当前影片，「查看的影片 ≠ 当前影片」这个状态在新结构下不存在；载入统一由影片菜单完成，按钮无对象可挂 |
| 2 | §4.5 菜单下方常驻安全底线小字 | 落在菜单的 `accessibilityHint` 与重制确认弹层正文 | 原生 `Menu` 只有一列可选中行，塞不进常驻说明；两页常驻一行小字是为一句设计冗余文案付视觉债 |
| 3 | §4.3 菜单项「重制（收起当前影片，开一部空白影片）」 | 菜单项只写「重制」 | 原生菜单项是单行文本，括注会被截断；括注的完整说法本来就在确认弹层里 |
| 4 | §3.1 `deleteEverything()` 改名 `deleteCurrentFilm()` | 语义再收窄为**只删这部影片**，不再顺带清孤儿文件 | 二者是两件事：删影片删的是它的素材，孤儿清理删的是无主文件。混在一个动作里会让「删除失败补偿日志」同时承载两种意图 |
| 5 | §6.3-4 `seed-simulator.py` 配合 `-preselectFilm` | 另加 `--legacy` 模式 | 迁移是本方案最高风险项，需要一条可重复执行的「造旧数据 → 启动 → 核对迁移结果」的验收路径 |
| 6 | — | 导出页删除按钮的禁用判据从 `shots.isEmpty` 改为 `currentFilm?.isBlank` | `shots.isEmpty` 会把「起了名字但还没加镜头」的影片也判成「没什么可删的」，而全应用只有这一个删除入口，那部影片就再也删不掉 |
