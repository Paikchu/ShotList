### R-15 · 用户把导出包交给 AI agent 时，包里应带上粗剪任务说明与素材参数，agent 不用追问就能剪出成片和中间工程文件

**验证状态：** 隔离测试实测（任务说明草案已在 9.18Vlog 导出包的副本上试剪通过，见[试剪记录](../export/试剪记录-9.18Vlog.md)）；App 侧待实现

**代码位置：** 待实现。预计 ShotList/Support/ExportPackageBuilder.swift · `buildChecked`（每条素材落盘后读参数）、`writeTextGuide`（瘦身为逐镜内容）、新增 `AGENTS.md` / `CLAUDE.md` / `manifest.json` 三个写入函数；素材参数读取用 AVFoundation，与 `MediaTranscode` 一样单独成文件。说明正文、第 4 节生成规则与 manifest 字段见[粗剪任务说明模板](../export/粗剪任务说明模板.md)

**预期结果：** 导出包根目录新增 `AGENTS.md`（粗剪任务说明）、`CLAUDE.md`（只有一行 `@AGENTS.md`）、`manifest.json`（逐镜内容原文与素材实测参数）。在解压后的目录里新开一个 Claude Code 会话，只说「按 AGENTS.md 完成粗剪」，agent 全程不提问，产出说明第 3 节列出的全部文件，并通过第 7 节的验收。

**需求详情**

**当前行为：** 包里给 AI 的只有「分镜文字内容指南.md」（逐镜内容与素材对应、处理规则）和「剪辑风格.md」（用户写的要求）。没有粗剪流程、交付物清单和验收标准，也没有机器可读的素材参数，agent 要靠用户一步步口头引导。用用户真实导出的 9.18Vlog 包实测，这些坑都要靠 agent 自己撞：

- 12 条主素材里 11 条是 HLG HDR（杜比视界 8.4），1 条是 SDR；不先转 SDR 直接混剪，HDR 镜头发灰。
- 5 条的第一条音轨是 APAC 空间音频，ffmpeg 解不了，最常见的命令直接报错；而且音轨顺序每条不同（5 条 APAC 在前、7 条 AAC 在前），不能对所有素材用同一个映射。
- 11 条是横向编码加旋转元数据，按编码宽高算画幅会算错；帧率混有 30 / 59.94 / 60，多数是可变帧率。
- 指南里的时长只精确到秒（0.718 秒写成 0:01，见 [P2-62](../issues/open-issues.md#p2-62)），「拍摄时间」对相册导入的素材其实是导入时间（见 [P2-61](../issues/open-issues.md#p2-61)）。
- 包里没说要交哪些产物、放在哪、怎么自检。

**目标行为：**

1. **新增 `AGENTS.md`：** 正文按[粗剪任务说明模板](../export/粗剪任务说明模板.md)生成。通用部分原样写入；片名、交付物文件名、标签名按本片填；第 4 节「本包素材情况」按实际素材生成，只列本包真实存在的情况（生成规则见模板）。
2. **新增 `CLAUDE.md`：** 只有一行 `@AGENTS.md`。Claude Code 2.1.277 起没有 CLAUDE.md 时才会读 AGENTS.md，更早的版本只读 CLAUDE.md（用户本机是 2.1.210）。
3. **新增 `manifest.json`：** 字段见模板「manifest.json 字段」一节，示例见 [manifest示例.json](../export/manifest示例.json)。参数从**打进包里的那份文件**读（选了转码就读转码结果）；时长精确到毫秒，时间用带时区的 ISO 8601；每条给出 `preferredAudioIndex`。
4. **指南瘦身：** `分镜文字内容指南.md` 去掉处理规则，只留逐镜内容与素材对应。规则只留在 `AGENTS.md` 一处——两份规则会打架，旧版指南就写着「分镜描述不是字幕」，与现在把上屏文字写在内容里的写法相反。
5. **读不出参数不中断导出：** 某条素材读不出轨道信息时，manifest 里对应字段写 `null`，`AGENTS.md` 第 4 节写明哪条没读到，打包照常完成。
6. **界面不变：** 导出页不加设置项，用户不需要为这件事做任何选择。

**范围：** `ExportPackageBuilder` 的包内文件与新增的 AVFoundation 参数读取；README 里导出包结构那一段。

**明确不做：**

- App 不做剪辑，也不加「入出点 / 选条」这类标记：选段交给 agent 看联系表决定，理由写进剪辑报告。要在 App 里标记另立需求。
- 不做 Mac 端的 skill 或脚本：说明跟着导出包走，换 agent、换电脑都能用。
- 不改导出格式选项、命名规则，也不改 `分镜清单.csv`、`导出说明.txt` 给人看的定位。
- 不在本需求里修 [P2-59](../issues/open-issues.md#p2-59)～[P2-62](../issues/open-issues.md#p2-62)，它们单独登记。

**对其他功能的影响：**

- 导出时每条素材多一次元数据读取（毫秒级），打包总耗时基本不变；包体积多几十 KB。
- 既有测试里断言指南规则文字的用例，随指南瘦身一起更新。
- 说明依赖 Mac 上的 ffmpeg（带 libass）、`avconvert`、Python；缺工具时说明里写了降级做法，产出会少烧录文字或少工程文件。
- [P2-62](../issues/open-issues.md#p2-62) 的「指南要求以取整时长为准」在本需求落地后不再成立（规则移出指南、时长以 manifest 为准），实现时一并核对。

**推断（未经用户确认）：**

- 模板里标「待确认」的三条剪辑规则按试剪时的做法写：① 素材短于文字阅读时间时不变速、不定格，只在报告里写明（9.18Vlog 的 08、09 就是这样）；② 关键画面在首尾时可以不避开首尾 0.3 秒；③ 单镜在上限内按画面需要加长，总长落在要求范围内即可。
- 默认字幕样式（下方字幕块中心约 71% 屏高、上方文字顶边距约 2%、白字黑描边、字高约 4.4% 屏高）取自剪辑风格页的示例文字。
- 「本片用到的标签」从模板库的标签名里筛出内容行首实际出现的；用户写了模板之外的标签时，那一行按描述处理，agent 会在报告里列出来。

**定级依据：** 定为 P2（用户未指定级别，按规则判定，如需上调请说明）。现在的导出包加上用户口头引导也能完成粗剪，本条是导出能力的增强，不阻断从拍摄到导出的主路径。

**验收方法**

1. 前置环境：模拟器安装 Debug 构建。准备一部影片，素材要覆盖：相册导入的 iPhone 原片（HLG HDR + APAC 空间音轨）、SDR 片段（模拟器没有摄像头，可用 `Tools/seed-simulator.py` 灌入）、一个拍了多条的镜头、一个未拍的镜头；镜头内容按模板写「下方字幕」「上方角标」这类标签行；写一段剪辑风格。
2. 「导出」页范围选「全部」、格式选「原片」，打包后把压缩包传到 Mac 解压。
3. 检查包内：根目录有 `AGENTS.md`、`CLAUDE.md`、`manifest.json`；`AGENTS.md` 的片名、交付物文件名正确，第 4 节只列本包存在的情况（HDR、APAC 音轨、旋转、混合帧率、短素材、备用片段、未拍镜头）；`manifest.json` 与 `ffprobe` 实测一致（时长到毫秒、`displaySize`、`hdr`、音轨顺序与 `preferredAudioIndex`）；`分镜文字内容指南.md` 里不再有处理规则。
4. 在解压目录新开一个 Claude Code 会话（不带本需求的上下文），只说「按 AGENTS.md 完成粗剪」。
5. 观察结果：agent 全程不提问；`输出/` 下说明第 3 节的文件齐全；说明第 7 节的验收全部通过；人工看 `中间/抽检/成片抽帧.jpg`：文字完整、字高约 4.4% 屏高、各镜颜色一致、未拍的镜头没有出现；`剪辑报告.md` 写明了取舍与降级。
6. 失败判据：agent 要追问才能继续；成片里 HDR 镜头发灰；有素材因 APAC 音轨报错；上屏文字与分镜原文有任何增删改；工程文件读回的切点与决策表不一致；`manifest.json` 与 ffprobe 实测不符；第 4 节列出了本包并不存在的情况。
