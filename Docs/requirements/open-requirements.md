### R-1 · 用户在任何一屏读到的文案都应短、直述、只说下一步做什么，而不是像一段解释给自己听的旁白

**验证状态：** 待验证

**代码位置：** 待实现。现状分布在 ShotList/Views/ 全部界面文件与 ShotList/Models/ShotStore.swift（错误文案）、ShotList/Support/ExportPackageBuilder.swift（包内文本）。典型落点见「需求详情」。

**预期结果：** 全应用的按钮、标题、空状态、说明脚注、确认弹层、错误提示统一到一套写法：**一句话说清这是什么或该做什么**，取舍与背景只在真会影响用户决定时才出现，并且放在脚注而不是主文本里。无障碍标签与提示同步跟着改，不留两套说法。

**需求详情**

**当前行为：** 界面上大量文案是「解释型长句」——把设计取舍、实现原因、边界条件都写进了用户能看到的位置，读起来像旁白或说明书，而不是产品语气。抽样（全部为当前代码中的原文）：

- `ClipOptionsSheet`：脚注「描述写「拍什么」，字幕与角标写「画面上显示什么」。这两样会被剪辑侧原样使用，不会替你改写；留空就是这一镜不出。」；提示「打开相机，给这个镜头再录一条，之前拍的会保留」「从照片图库里选一段或多段已经拍好的视频加进来，可以一次选多段」「把上一镜的角标文字抄过来，抄完可以再改」；占位回退「未写字幕，成片上不出字」。
- `ExportView`：「只会导出《X》的镜头，别的影片不会被一起带走。」「还没有可导出的视频。先到「分镜」里拍一段，再回来导出。」「未写，这次导出不带风格要求」「你写的那段剪辑要求：怎么剪、要什么观感；没写就不产出这个文件」「每个镜头最新的一条（主素材）；同一个分镜拍了好几条时，末尾的片段序号用来区分候选，只拍一条时不带」。
- `FilmBar` / `FilmActionDialogs`：「点这里给影片起个名字」「留空也可以，之后在影片菜单里按日期找得到。」「《X》会留在影片库里，随时可以载入继续拍。现在打开一部空白影片。」
- `CameraChrome` / `CameraCaptureView`：「这个分镜还没有写描述」；录制按钮提示「拍完可以回看，确认后再保存。同一个镜头可以拍很多条，后拍的不会覆盖前面的。」；权限页「分镜助手只会用摄像头录制你的分镜视频。视频保存在这台 iPhone 上，不会上传到任何地方。」
- `CameraSettingsSheet`：「60 fps 画面更顺、方便后期慢放，24 fps 更接近电影的质感。可选的帧率取决于分辨率。」
- `FilmStyleView`：「这段话会原样写进导出包的「剪辑风格.md」，交给剪辑工具照着剪。写到的按你写的来，没写的由它按常规判断；留空就表示这条片子没有特别要求。」
- `ShotStore` 的错误文案：「无法读取分镜记录，已暂停编辑和文件清理，原文件不会被覆盖。请恢复可用的分镜记录后重试。」——「请恢复可用的分镜记录」对用户不可执行。

**目标行为：** 先定一份写法约定，再按约定逐屏重写：

1. **按钮与菜单项只写动词短语**，不解释后果（后果放确认弹层）。
2. **主文本一句话**，超过一句的解释下沉到 `footer` / `accessibilityHint`；同一件事不在同屏说两遍。
3. **空状态**只写「这里还没有 X」+ 一个动作按钮，不写鼓励语与流程复述。
4. **错误提示**必须给出用户能执行的下一步；做不到时改写成「这次没成功，已保留原来的内容」这类可执行的兜底，不把内部状态（「已暂停编辑和文件清理」）写给用户。
5. **不把设计理由写进界面**（「这是有意的」「别的影片不会被一起带走」这类），理由留在代码注释里。
6. 无障碍标签 / 值 / 提示与可见文案同步更新，避免出现「屏幕上一句、朗读另一句」。

**范围：** ShotList/Views/ 下的全部用户可见字符串，加上 `ShotStore` 的 `loadError` / `saveError` 文案、`ExportError` 的 `errorDescription`、`ExportTranscodeOption.detail` / `title`。

**明确不做：** 不改导出包内的 `分镜文字内容指南.md` 与 `剪辑风格.md`——那两份是写给剪辑工具 / AI 读的，长句与显式约束是它们的功能，属于本需求之外的另一类文本。不做多语言（`AppLocale` 仍固定简体中文）。不改功能与信息架构，只改字。

**对其他功能的影响：** `ExportPackageBuilder.writeReadme` 里的 `导出说明.txt` 对用户可见，属于本需求范围，但它与包内给 AI 的两份文件共用一些变量，改写时不要连带改到那两份的措辞。

**验收方法**

1. 前置环境：模拟器安装 Debug 构建，准备一部含 5 个镜头（3 个已拍、2 个未拍）、写过标题与风格描述的测试影片。
2. 按「分镜 → 镜头面板 → 取景页（真机）→ 历史 → 导出 → 剪辑风格」的顺序逐屏走一遍，对每一屏截图。
3. 逐条核对：屏幕上是否还存在超过一句话的主文本；按钮文案是否只剩动词；空状态是否只剩一句话加一个按钮。
4. 打开 VoiceOver 再走一遍同样的路径，确认朗读内容与屏幕文字一致，没有遗留旧说法。
5. 用隔离测试数据触发一次保存失败（例如把 Application Support 副本设为只读），确认错误提示里写的是用户能执行的下一步。
6. 失败判据：任一屏仍出现解释实现取舍的句子（例如「别的影片不会被一起带走」「这是有意的」），或可见文案与无障碍朗读不一致。

**实现状态：** 未开始

**验证结果：** 待验证；完成后记录环境、逐屏核对结果与截图位置。

### R-2 · 用户打开导出页时应先看到「这次导什么、结果在哪」，说明性内容按当前影片实际会产出的东西给

**验证状态：** 待验证

**代码位置：** 待实现。现状为 ShotList/Views/ExportView.swift · `body`（第 44–105 行）的九个 Section 顺序、`contentsSection`（第 302–313 行）、`exampleAlternateFileName`（第 345–353 行）、`computerSection`（第 428–450 行）

**预期结果：** 导出页一屏之内能回答「我要导什么 / 导出结果在哪 / 现在能不能导」。参考性内容（包里有什么、怎么取到电脑）收起为可展开的一节，且列出的文件与当前影片真的会产出的文件一致。

**需求详情**

**当前行为：** 导出页把九个 Section 平铺在一列里：素材概览、剪辑风格、打包导出、结果、已过期提示、压缩包里有什么（6 行固定说明）、单独分享某个镜头（每个已拍镜头一行）、用数据线取到电脑（2 行静态说明）、维护。其中：

- 「刚刚生成的导出包」插在「打包导出」与「压缩包里有什么」之间，生成后要往回找；
- 「压缩包里有什么」与「用数据线取到电脑」加起来 8 行，是一次性读的参考资料，却常驻在主路径中间；
- `contentsSection` 无条件列出 `备用片段/…`（`exampleAlternateFileName`）与 `剪辑风格.md`，但当前影片可能没有任何拍了多条的镜头（包里不会有「备用片段」目录），也可能没写风格描述（`writeStylePrompt` 在描述为空时不产出文件，见 ExportPackageBuilder.swift:751）。列出来的文件解压后找不到。

**目标行为：**

1. 顺序改为：素材概览 → 打包导出（范围 / 格式 / 生成按钮 / 进度）→ 生成结果（生成后置顶到概览之下）→ 剪辑风格 → 单独分享 → 参考资料（可展开）→ 维护。
2. 「压缩包里有什么」与「用数据线取到电脑」合并成一个默认收起的「参考资料」小节（`DisclosureGroup`）。
3. `contentsSection` 按当前影片实际会产出的文件列：没有多条片段的镜头就不列「备用片段/」，没写风格描述就不列「剪辑风格.md」。判据要与 `ExportPackageBuilder` 的产出条件同源，不另写一套。
4. 「已过期」提示紧跟在结果一节之后，不单独占一个无标题 Section。

**范围：** 只动 `ExportView` 的版式与条件展示。

**明确不做：** 不改导出包的目录结构、命名规则与包内文件内容；不改 `ExportScope` / `ExportTranscodeOption` 的取值；文案改写归 [R-1](#r-1)，本条只管结构与条件。

**对其他功能的影响：** `contentsSection` 改成条件展示后，它与 `ExportPackageBuilder` 的产出条件必须保持同源，后续改包内结构时两处要一起改；在实现说明里记录这条耦合。

**验收方法**

1. 前置环境：模拟器安装 Debug 构建。准备三部测试影片：A 有多条片段且写过风格描述；B 每镜只有一条片段、没写风格描述；C 一个镜头都没拍。
2. 切到影片 B，打开导出页：确认「压缩包里有什么」里**没有**「备用片段/」和「剪辑风格.md」两行。
3. 切到影片 A，打开导出页：确认两行都在，且示例文件名与随后真实生成的包内文件名一致（解压比对）。
4. 在影片 A 上点「生成导出包」，生成完成后不滚动屏幕，确认结果一节出现在首屏可见范围内。
5. 确认「参考资料」默认收起，展开后包含原「压缩包里有什么」与「用数据线取到电脑」的全部内容。
6. 切到影片 C：确认生成按钮禁用且给出原因，维护一节的删除入口按现有规则可用。
7. 失败判据：列出的文件在实际导出包里不存在；生成完成后结果一节仍需要向下滚动才能看到。

**实现状态：** 未开始

**实现说明：** 待实现；完成后记录条件展示的判据放在哪里，以及与 `ExportPackageBuilder` 的耦合点。

**验证结果：** 待验证；完成后记录环境、三部测试影片的实际观察结果与解压比对结论。

### R-3 · 用户在导出转码进行中改主意时，应当能直接停下这次导出

**验证状态：** 待验证

**代码位置：** 待实现。现状为 ShotList/Views/ExportView.swift · `buildSection`（第 189–247 行）、`buildProgress`（第 251–262 行）；ShotList/Support/ExportSession.swift · `invalidate()`（第 20–29 行）、`cancellation`（第 18 行）；ShotList/Support/ExportPackageBuilder.swift · `ExportCancellation`（第 159–165 行）、`run.checkCancellation()`（第 411、426、509 行）

**预期结果：** 打包进行中，进度条旁边有一个「停止」入口；点它之后打包在下一段素材之前停下，界面回到可以重新选范围 / 格式的状态，临时目录里不留半成品。

**需求详情**

**当前行为：** 取消能力在底层已经完整实现——`ExportCancellation` 是原子标志，`build` 在每个镜头、每条片段与打包前都调 `run.checkCancellation()`，`ExportSession.invalidate()` 会置位它。但界面上没有任何入口调用 `invalidate()`：生成按钮在 `export.isBuilding` 时被禁用，进度区只有一条 `ProgressView` 和一行文字。唯一能触发取消的是去改「导出范围」或「视频格式」Picker（它们的 `onChange` 会调 `invalidate()`），这是副作用，不是取消，用户也不会知道。

选了「H.264 · 1080p」或「HEVC · 1080p」时每段素材要重编码，素材多时整个过程是分钟级；期间用户只能等，或退出应用。

**目标行为：**

1. `export.isBuilding` 为真时，在进度区右侧显示「停止」按钮，点击调 `export.invalidate()`。
2. 停止后不弹错误（取消不是失败——`ExportPackageBuilder` 已经把 `CancellationError` 与转码失败分开，见第 478 行），进度区收起，界面回到未生成状态。
3. 停止后不要显示「分镜、素材或导出范围已变化，请重新生成导出包」——那句话说的是另一回事；为「用户主动停止」给一句独立说明，或什么都不显示。
4. 确认临时目录里不留 `ShotListExport/<uuid>/`（`buildChecked` 的 `defer` 已经负责回收工作目录，验收时核对）。

**范围：** `ExportView` 加入口，`ExportSession` 按需要区分「被用户停止」与「输入变化作废」两种失效原因。

**明确不做：** 不做断点续传；不做后台继续导出；不改转码实现。

**对其他功能的影响：** `isStale` 目前一个布尔值同时表达两种失效原因，拆分时要确认 `build()` 完成后的 `guard generation == token, isCurrent()` 分支（ExportSession.swift:54–59）仍然把「迟到的结果」正确丢弃。

**定级依据：** 导出是主路径的最后一步，但默认档位「原片」不转码、耗时短，且用户可以退出应用终止，有绕行方式，因此定为 P2 而不是 P1。

**验收方法**

1. 前置环境：模拟器安装 Debug 构建，准备一部至少 6 个镜头都已拍、素材较大的测试影片（隔离数据）。
2. 在导出页把「视频格式」选为「H.264 · 1080p」，点「生成导出包」。
3. 等进度文字走到「正在转码 2 / 6 段」左右，点「停止」。
4. 观察：进度区在下一段素材开始前收起；不弹「导出失败」；「刚刚生成的导出包」一节不出现；界面上的范围 / 格式 Picker 与生成按钮恢复可用。
5. 用「文件」App 或调试命令检查应用临时目录，确认没有残留的 `ShotListExport/<uuid>/` 工作目录。
6. 再点一次「生成导出包」，确认能正常走完并产出可分享的包。
7. 失败判据：停止后弹出错误提示；或停止后进度仍继续推进到下一段；或临时目录留下工作目录。

**实现状态：** 未开始

**实现说明：** 待实现；完成后记录「用户停止」与「输入变化作废」在 `ExportSession` 里如何区分。
