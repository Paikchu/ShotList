### R-1 · 用户在任何一屏看到的界面语言都应是标准的软件提示语，能用图标或版式表达的就不写说明文字

**验证状态：** 模拟器实测（除下列未验证项）；无障碍标签为代码级确认，回看页与失败提示待真机

**代码位置：** 现状分布在 ShotList/Views/ 全部界面文件、ShotList/Support/DesignSystem.swift（进度环）、ShotList/Models/ShotStore.swift（存储错误）、ShotList/Models/Shot.swift 与 Film.swift（状态、无障碍与进度文本）、ShotList/Support/ExportPackageBuilder.swift（`ExportScope.title`、`ExportTranscodeOption.detail`、`ExportPackage.summary`、`ExportProgress.text`、`ExportError`、`导出说明.txt`）、ShotList/Camera/CameraRecorder.swift（相机错误）。典型落点见「需求详情」。

**预期结果：** 全应用的按钮、标题、空状态、确认弹层、错误提示统一成软件界面惯用的短语（动词 / 名词 / 图标 + 数字），不再是解释给用户听的自然语言句子。图标、数字、版式、虚线占位已经能表达的信息，不再另写文字。无障碍标签与提示同步跟着改，不留两套说法。

**需求详情**

**当前行为：** 界面上大量文案是「解释型长句」——把设计取舍、实现原因、边界条件都写进了用户能看到的位置，读起来像旁白或说明书，而不是软件界面的提示语；有图标或版式能说清的地方也还在配一句文字。抽样（全部为当前代码中的原文）：

- `ClipOptionsSheet`：脚注「描述写「拍什么」，字幕与角标写「画面上显示什么」。这两样会被剪辑侧原样使用，不会替你改写；留空就是这一镜不出。」；提示「打开相机，给这个镜头再录一条，之前拍的会保留」；按钮「从相册再添加」「清空这个镜头的 N 段片段」。
- `ExportView`：「只会导出《X》的镜头，别的影片不会被一起带走。」「还没有可导出的视频。先到「分镜」里拍一段，再回来导出。」；「压缩包里有什么」每个文件下一行说明；数据线取到电脑的两段路径说明。
- `FilmBar` / `FilmActionDialogs`：「点这里给影片起个名字」「留空也可以，之后在影片菜单里按日期找得到。」「《X》会留在影片库里，随时可以载入继续拍。现在打开一部空白影片。」
- `CameraChrome` / `CameraCaptureView`：「这个分镜还没有写描述」；录制按钮提示「拍完可以回看，确认后再保存……」；权限页整段说明；「正在保存到分镜…」「正在启动相机…」。
- `CameraSettingsSheet`：分辨率、帧率脚注各一段解释。
- `FilmStyleView`：两段脚注与「可以写这些」下每条带例句的清单。
- `ShotStore` 的错误文案：「无法读取分镜记录，已暂停编辑和文件清理，原文件不会被覆盖。请恢复可用的分镜记录后重试。」——「请恢复可用的分镜记录」对用户不可执行，「已暂停编辑和文件清理」是内部状态。

**目标行为：** 先定一份写法约定，再按约定逐屏重写：

| 场景 | 写法 |
|---|---|
| 按钮、菜单项 | 动词或动宾短语，一般不超过 4 个字：拍摄、导入、分享、删除、完成；不解释后果（后果放确认弹层）。 |
| 有通用图标的操作 | 图标为主：关闭、更多、展开 / 收起等只画图标，名称写进无障碍标签。列表与菜单里的动作图标 + 短动词并列。 |
| 标题、分组名 | 名词，不超过 4 个字；同一屏里分组标题与行标题不重复。 |
| 状态与统计 | 图标 + 数字（✓ 3/5、时长、体积），不写「已拍 3 / 5 个镜头」这类句子；图标含义不明确的地方保留 1–2 字标签。 |
| 空状态 | 图标 + 一个名词短语（「无镜头」）+ 至多一个动作按钮，不写说明句与鼓励语。 |
| 确认弹层 | 标题为「动作 + 对象 + ？」；正文只写不可逆后果或波及数量（「N 段视频将被删除，无法恢复。」），无后果可写时不写正文；按钮为动词与「取消」。 |
| 错误提示 | 「动作 + 失败」加用户能执行的一步（重试、释放空间、改用原片）；不把内部状态与设计取舍写给用户；做不到时写「已保留原内容」。 |
| 输入框 | 字段名靠图标与短标签常驻，占位只留字段名或一个短示例，不写「例如：…」引导语。 |
| 脚注、提示、无障碍 hint | 默认不写。只有会改变用户决定的取舍（导出格式的兼容与体积）保留一行；hint 只补标签没说清的操作结果。 |
| 设计理由 | 不进界面，留在代码注释里。 |

**范围：** ShotList/Views/ 下的全部用户可见字符串及其无障碍标签，加上 `ShotStore` 的 `loadError` / `saveError` 文案、`ExportError` 的 `errorDescription`、`ExportScope.title`、`ExportTranscodeOption.detail`、`ExportPackage.summary` 与导出进度文本、相机错误文案、`导出说明.txt`。允许为替换文字而新增或调整 SF Symbols，但不改布局结构、功能与信息架构。

**明确不做：** 不改导出包内的 `分镜文字内容指南.md` 与 `剪辑风格.md`，也不改 `分镜清单.csv`——那几份是写给剪辑工具 / AI 读的，长句与显式约束是它们的功能。不改「剪辑风格」页输入框里的整段示例（它是可编辑内容的样本，不是界面说明）。不做多语言（`AppLocale` 仍固定简体中文）。不改功能、导航与数据；需要重排结构的部分归 [R-2](delivered-requirements.md#r-2)。

**对其他功能的影响：** `ExportPackageBuilder.writeReadme` 里的 `导出说明.txt` 对用户可见，属于本需求范围，但它与包内给 AI 的两份文件共用一些变量，改写时不要连带改到那两份的措辞。少数现有测试断言了可见文本（`ExportProgress.text`、`ExportError` 的描述），随文案同步更新断言。

**验收方法**

1. 前置环境：模拟器安装 Debug 构建，`Tools/seed-simulator.py` 灌入演示数据（含 5 个镜头、3 个已拍、写过标题与风格描述的影片）。
2. 按「分镜 → 镜头面板 → 取景页（`-chromeDemo` / `-cameraDemo`；真实拍摄需真机）→ 历史 → 导出 → 剪辑风格」的顺序逐屏走一遍，对每一屏截图，含空状态、确认弹层与错误提示。
3. 逐条核对约定表：屏幕上是否还存在解释设计取舍或复述操作步骤的句子；按钮是否只剩动词或图标；状态是否是图标 + 数字；空状态是否只剩「图标 + 名词 + 一个按钮」。
4. 打开 VoiceOver（或读无障碍树）再走一遍同样的路径，确认朗读内容与屏幕文字一致，图标按钮都有名称，没有遗留旧说法。
5. 用隔离测试数据触发一次保存失败（例如把 Application Support 副本设为只读）与一次导出失败，确认提示里是「失败 + 可执行的一步」。
6. 失败判据：任一屏仍出现解释实现取舍的句子（例如「别的影片不会被一起带走」「这是有意的」）；图标按钮没有无障碍名称；可见文案与无障碍朗读不一致；文字被替换成图标后无法判断该控件做什么。

**实现状态：** 已实现，待验证

### R-11 · 用户想先拍后补描述时，应能长按分镜页的加号展开「快速拍摄」卡片，点卡片直接开拍，拍完直接落到该镜头的描述页

**验证状态：** 模拟器实测（除下列未验证项）；真机录制 →「使用」→ 描述页这一路待真机实测

**代码位置：** ShotList/Views/ShotListView.swift · `toolbarContent` 里的加号（第 349–371 行，`Image` + 点按 / 长按手势 + `popover`）、`QuickShootCard`（第 484 行）、卡片收起后开相机的 `onChange(of: isShowingQuickCard)`（第 86 行）与 `quickShoot()`（第 413 行）；ShotList/Views/ShotFlowModifier.swift · `ShotCaptureRequest`（第 34 行）、`onChange(of: captureRequest)`（第 136 行）、`startCapture` / `finishQuickShoot`（第 242 / 252 行）、`drainQueue` 的导入分支（第 230 行）、`importMovies(…opensDescription:)`（第 269 行）；未改动 ShotList/Views/CameraCaptureView.swift 与 ShotList/Views/ClipOptionsSheet.swift（复用其 `save` 后 `dismiss()` 与 `autoFocusNote`）

**预期结果：** 分镜页右上角加号：点一下仍是添加一个镜头；长按从加号处展开一张**快速拍摄**卡片——2×2 个图标大小的方卡，中间是 2×2 宫格图标和名称，整张可点（原来的「添加 3 个 / 5 个 / 10 个」已按用户指示移除）。点卡片：在影片末尾新建一个空镜头，直接进入它的相机取景页，中间不经过镜头面板。拍完点「使用」、相机关闭后，直接打开这个镜头的面板（描述页），光标已在描述框里，写完点「完成」回到分镜页，列表滚到这个新镜头并短暂高亮。

**需求详情**

**当前行为：** 「先拍后写」要走：点加号（新建空镜头并打开面板、光标进描述框）→ 先关掉键盘或略过描述 → 点「拍摄」（面板收起、相机弹出）→ 录制、点「使用」→ 相机关闭后回到分镜页 → 再点这张卡片打开面板 → 写描述。拍完之后没有任何东西把用户带到「补描述」这一步，要自己找回那张卡。登记时加号长按的菜单是纵向三项批量添加（3 / 5 / 10 个），没有「直接拍」的入口。

**目标行为：**

1. **长按加号展开「快速拍摄」卡片。** 加号点一下仍是「添加」一个镜头（行为、触感、落点都不变）。长按（约 0.35 秒，给一次中等触感）从加号处展开一张卡片：2×2 个图标大小的方卡，中间是 2×2 宫格图标（`square.grid.2x2`）和「快速拍摄」，整张可点；点卡片以外的地方收起卡片、什么都不做，长按松手也不会顺带新增镜头。原来的「添加 3 个 / 添加 5 个 / 添加 10 个」按用户追加的指示（登记当天）移除，不留替代入口。图标与卡片形态是用户的后续指示：图标由摄像机加号（`video.badge.plus`）换成 2×2 宫格；长按原先弹出的是系统菜单（一个小气泡），用户要的是「展开卡片」的效果。
2. **快速拍摄 · 开拍。** 点卡片：卡片先收起，收起后在当前影片末尾新建一个空镜头（编号接在末尾，与「添加」同一个 `store.addShot()`），并直接以该镜头进入相机取景页，效果等同镜头面板里点「拍摄」，给一次 `Haptics.impact(.light)`。整个过程不出现镜头面板。
3. **快速拍摄 · 收尾落到描述页。** 相机关闭时，若这个镜头已经存下至少一条片段（点「使用」，或先「保存并再拍」过再关闭），就直接打开它的镜头面板并把光标放进描述框（同 `autoFocusNote`，与新增 / 插入镜头后的落点一致）；用户下滑关掉面板（内容已自动保存，面板上没有「完成」按钮）后回到分镜页，列表滚到这个新镜头并高亮一下（同「在下方插入」的做法），让人看得见它落在哪儿。
4. **快速拍摄 · 取消不留痕。** 相机关闭时这个镜头一条片段都没有（点关闭 / 取消、权限说明页或「相机不可用」页点取消），就把这次新建的空镜头一并撤销，镜头数与编号回到点「快速拍摄」之前；不弹面板。
5. **相机不可用时走导入。** 相机页在无摄像头 / 无权限时提供「导入」：选中的视频导进这个新镜头，导入完成后同样直接打开它的描述页；这一路取消选片时不撤销空镜头（用户已明确要往里导入，行为与「点加号新增后不写内容就关面板」一样，留下的是普通的空镜头）。
6. **无障碍。** 加号对读屏是一个名为「添加」的按钮（默认操作＝添加一个镜头），提示为「长按快速拍摄」，并提供自定义操作「快速拍摄」——读屏用户不用长按也能触发，触发后直接开拍（不经过卡片）。

**范围：** 分镜页（`ShotListView`）的加号与长按卡片（含移除三项批量添加）；`ShotFlowModifier` 增加一个「从列表直接进相机，并在收尾时接着打开描述页」的入口。

**推断（未经用户确认）：**

- 「这个图标」按分镜页右上角的加号解读。最初把「展开成 2×2」解读为菜单变成四格的 2×2 图标宫格（原有三项加上「快速拍摄」），并按此实现；用户随后指示去掉三项批量添加、只保留「快速拍摄」，所以菜单只剩一项，不再是宫格。「快速拍摄」的图标起初沿用摄像机加号（`video.badge.plus`），用户随后指示换成 2×2 宫格样式，现为 `square.grid.2x2`。
- 「展开卡片页的效果」解读为从加号处弹出的一张 popover 卡片（约 2×2 个图标大小），不是整页或半屏 sheet；卡片里只有「快速拍摄」一个入口。如果用户要的是别的形态（更大的卡片、里面放多个入口、底部弹出的卡片页），需要说明。
- 「添加描述的页面」按现有的镜头面板（`ClipOptionsSheet`）解读，不新做页面。
- 「结束拍摄」解读为相机关闭且该镜头至少有一条片段；用户在相机里点「保存并再拍」只是继续拍，不算结束。

**明确不做：**

- 不改「点一下加号」的流程与空状态里的「添加」按钮。批量添加 3 / 5 / 10 个整体移除，不做替代入口；需要再要批量入口时另立需求。
- 不做「拍完一镜自动开下一镜」的连拍；本条一次只建一个镜头、拍完回到描述页。
- 不改相机页本身（取景、录制、回看、保存）与导入流程；不新增数据字段。
- 不给历史页加这个入口：历史页没有加号；它与分镜页共用 `ShotFlowModifier`，只需保证原有流程不变。

**对其他功能的影响：**

- **与 R-6 共用「从列表直接进相机」的入口。** 这里给 `ShotFlowModifier` 加的入口，[R-6](delivered-requirements.md#r-6)（未拍镜头的虚线加号直接拍摄）可以直接复用；两条谁先做，另一条接上即可，需要在实现说明里记录入口形态。
- **空镜头先落盘再进相机。** 相机页需要一个真实存在的镜头（编号、`addClip` 的目标），所以先新建再开相机，取消时再撤销（`store.delete`，撤销的是末尾镜头，其余编号不动）。进程在相机打开期间被杀会留下一个空镜头，与「加号新增后不写内容」同样是普通的空镜头，可手动删除。
- **弹层串行。** 相机 `fullScreenCover` 收起之后才能弹描述页，沿用 `drainQueue` 的串行呈现约束，不在相机还没收起时弹面板；与相机页里「导入」的排队互不冲突。
- **移除批量添加。** `ShotListView.addShots(count:)` 随菜单项一起删除；`ShotStore.addShots(count:)` 保留（`ShotStoreTests` 里有 2 处断言仍在用它），应用内已没有调用方。README 里「长按加号一次添加 3 / 5 / 10 个」的说法同步改掉；历史记录里提到批量添加的旧条目不动。
- **新增失败。** `store.addShot()` 返回 `nil`（读盘失败、落盘失败）时什么都不做，错误提示沿用既有的存储错误横幅。

**定级依据：** 定为 P2（用户未指定级别，按规则判定，如需上调请说明）。已有绕行方式（点加号 → 拍摄 → 回到分镜页再点卡片补描述），不阻断从拍摄到导出的主路径；属于「先拍后补描述」的效率增强。

**验收方法**

1. 前置环境：模拟器与真机各安装 Debug 构建。模拟器没有摄像头，只能验证到「点快速拍摄 → 出现相机不可用页」以及经「导入」落到描述页，录制、点「使用」这一路要真机。准备一部含 3 个镜头的影片；模拟器相册里先放入一段视频（`xcrun simctl addmedia`）。
2. 点一下加号：新增第 4 个镜头并弹出面板、光标在描述框（行为与改前一致）；下滑关掉面板。
3. 长按加号（约半秒）：从加号处展开一张「快速拍摄」卡片——方形、约 2×2 个图标大小，中间是 2×2 宫格图标和「快速拍摄」；没有「添加 3 个 / 5 个 / 10 个」；松手不会新增镜头。点卡片以外的地方：卡片收起，镜头数不变。
4. 长按加号点卡片：卡片收起后，末尾多出一个空镜头（编号 = 原镜头数 + 1），**直接**出现相机页（真机为取景，模拟器为「相机不可用」），期间没有镜头面板弹出；取景页标注的镜头编号是这个新镜头。
5. 真机：录一小段，点「使用」：相机关闭后镜头面板自动弹出，标题是新镜头的编号，光标已在描述框，头部缩略图是刚拍的这一条；键盘输入一句描述，下滑关掉面板：回到分镜页，列表滚到这个新镜头并短暂高亮，卡片上是描述与缩略图。
6. 真机：再走一次快速拍摄，录一条点「保存并再拍」，再录一条点「使用」：描述页里有两条片段。
7. 快速拍摄后不录制、直接关闭相机（真机点左上角关闭；模拟器点「取消」）：回到分镜页，末尾没有多出空镜头，镜头数与编号和点快速拍摄之前一致，没有面板弹出。
8. 真机：快速拍摄，录一条点「保存并再拍」，回到取景后点左上角关闭：镜头保留，直接打开描述页（有一条片段）。
9. 模拟器：快速拍摄 → 相机不可用页点「导入」→ 选一段视频：导入完成后自动弹出这个镜头的描述页，光标在描述框。再来一次，在选片界面点取消：回到分镜页，末尾留着一个空镜头，没有面板弹出。
10. 系统设置里关闭本应用的相机权限：快速拍摄走既有的权限说明页；点「取消」：空镜头被撤销。
11. 回归：在镜头面板里点「拍摄」拍完一条（真机）：仍是回到分镜页，不弹描述页；点「使用」之后停在分镜页。「历史」页点开镜头、拍摄、导入的流程与改前一致。
12. 打开 VoiceOver 聚焦加号：读作「添加」按钮，提示含「长按快速拍摄」；自定义操作里有「快速拍摄」，触发后进入相机。
13. 失败判据：点快速拍摄后先弹出镜头面板；拍完（或导入完）停在分镜页没有弹描述页；相机点取消后留下空镜头；描述页出现了但光标不在描述框；点一下加号的行为变了；新镜头编号没接在末尾，或已有镜头编号错乱；从面板「拍摄」进入的相机拍完也弹出了描述页；长按后仍是纵向小菜单或出现「添加 3 个 / 5 个 / 10 个」；长按松手后多出一个镜头；点卡片后相机没有弹出（页面停在半路、外观变成深色）；「快速拍摄」的图标不是 2×2 宫格。

**实现状态：** 已实现，待真机验收

**实现说明：**

- **长按卡片：** 加号不再是系统 `Menu`。`Menu` 只能显示成固定的小气泡，做不出卡片；工具栏里的 `Button` 上挂 `simultaneousGesture(LongPressGesture)` 又收不到长按（实测：长按松手只触发点击、新增一个镜头，卡片没有出现）。最终做法：`Image(systemName: "plus")`（44pt 命中区）上挂 `onTapGesture`（添加）与 `onLongPressGesture(minimumDuration: 0.35)`（展开卡片），再挂 `popover`，`presentationCompactAdaptation(.popover)` 保证 iPhone 上仍是从加号处展开的卡片而不是整页 sheet；卡片 `QuickShootCard` 是 132×132 的方卡（2×2 个 60pt 图标的大小），中间 40pt 的 `square.grid.2x2` 加「快速拍摄」，整张是一个无样式 `Button`。
- **无障碍补齐：** `Image` 不是按钮，所以 `accessibilityElement()` + 标签「添加」+ `.isButton` 特征 + 默认操作（添加）+ 自定义操作「快速拍摄」+ 提示「长按快速拍摄」。代价：失去系统按钮的按压反馈。
- **卡片收起后再开相机：** 点卡片先设 `pendingQuickShoot` 并收起卡片，`onChange(of: isShowingQuickCard)` 等 400 毫秒再走 `quickShoot()`。实测卡片一收起就弹相机，相机会被系统丢掉：页面停在半路，相机页的深色外观却已经生效，`ShotFlowModifier` 的 `cover` 也就卡住。
- **追加调整（用户指示）：** 第一版按 2×2 宫格做（两个 `ControlGroup`，四格：添加 3 / 5 / 10 个 + 快速拍摄），并已在模拟器验证；随后用户指示去掉三项批量添加、只保留「快速拍摄」，于是 `ControlGroup` 一并去掉、菜单只剩一项（其后又改成长按卡片，见上一条），同时删除随之无用的 `ShotListView.addShots(count:)`。`ShotStore.addShots(count:)` 保留（`ShotStoreTests` 仍引用），应用内已无调用方。
- **从列表直接进相机的入口：** `ShotFlowModifier` 增加绑定 `captureRequest: ShotCaptureRequest?`（`shotID` + `isQuick`），`shotFlow(sheet:captureRequest:)` 默认传常量 `nil`，历史页不受影响。收下请求后立刻清空、以该镜头设置 `cover = .camera`。[R-6](delivered-requirements.md#r-6) 可以直接复用这个入口，传 `isQuick: false` 即可（不做收尾）。
- **收尾判定放在 `ShotFlowModifier`：** `quickShotID` 记着正在快速拍摄的镜头，相机 `fullScreenCover` 收起后由 `drainQueue` → `finishQuickShoot` 处理：有片段 → 下一轮主循环里 `sheet = .options(shot, autoFocusNote: true)`；没有 → `store.delete(shot)` 撤销空镜头。相机页里选「导入」时排队的导入优先：`drainQueue` 把 `quickShotID` 折成 `pickerOpensDescription` 交给选片，`importMovies` 在全部成功、且此时没有别的弹层时打开描述页；`pickerOpensDescription` 每次呈现选片都重新赋值，取消选片留下的值不会串到下一次导入。
- **高亮与滚动：** `quickShoot()` 新建镜头后把它记进已有的 `pendingFlashID`，描述页关掉时走原来的「滚过去并高亮」；取消撤销后该镜头已不存在，`onChange(of: sheet?.id)` 里加了一句存在性判断，不去指一个已删除的镜头。
- **措辞：** 合入 [R-9](delivered-requirements.md#r-9) 之后面板里的输入框标签是「内容」（描述、字幕、角标合并为一个框），本条文里的「描述框 / 描述页」指这个框和这一页，光标落点不变。
- **没有改** `CameraCaptureView` 与 `ClipOptionsSheet`；面板里点「拍摄」、卡片、历史页的既有流程不带 `quickShotID`，收尾逻辑对它们是空操作。
- **已知取舍：** 相机不可用而走导入时，取消选片会留下空镜头（用户已明确要往里导入，与「点加号新增后不写内容就关面板」一样，是普通的空镜头）；导入部分失败时先给「导入失败」提示，不自动打开描述页。

### R-13 · 用户在主屏上想一步开拍时，应能添加小号（2×2）桌面小组件，点一下直接进入「快速拍摄」

**验证状态：** 模拟器实测（除下列未验证项）；真机上的添加与点击、签名、录制后落到描述页待真机实测

**代码位置：** ShotListWidget/QuickShootWidget.swift · `QuickShootWidget`（`supportedFamilies([.systemSmall])`、`widgetURL`）；ShotList/Support/QuickShootLink.swift · `QuickShootLink`（应用与小组件两个 target 共用的链接约定）；ShotList/Support/ModalPresentation.swift · `isActive` / `waitUntilIdle`；ShotList/Views/RootTabView.swift · `quickShootRequest`（第 16 行）与 `onOpenURL`（第 67 行）；ShotList/Views/ShotListView.swift · `quickShootRequest` 绑定与 `init`（第 12、38 行）、`onChange(of: quickShootRequest, initial: true)`（第 104 行）、`quickShootFromWidget()`（第 442 行）；project.yml · `ShotListWidget` target、应用的 `CFBundleURLTypes` 与对小组件的依赖；未改动 ShotList/Views/ShotFlowModifier.swift、CameraCaptureView.swift、ClipOptionsSheet.swift

**预期结果：** 主屏可以添加「分镜助手」的小号（2×2 格）小组件，画面是 2×2 宫格图标加「快速拍摄」。点一下：应用打开（冷启动或从后台回来），停在「分镜」标签，在当前影片末尾新建一个空镜头并直接出现它的相机取景页，中间不经过镜头面板；之后的收尾（拍完落到描述页、取消撤销空镜头）与 R-11 完全一致。

**需求详情**

**当前行为：** 长按主屏上的「分镜助手」图标没有任何可展开的内容：工程没有小组件扩展，Info.plist 没有主屏快捷操作与 URL scheme。R-11 的「快速拍摄」只在应用里面——要开拍得先点图标、等启动、切到分镜页、长按右上角加号、再点卡片。R-11 登记时把用户说的「这个图标」解读成了分镜页的加号（条目里标注过「未经用户确认」）；用户随后说明想要的是主屏上的图标能展开成 2×2，并选定做小号小组件。

**目标行为：**

1. **小组件。** 新增小组件扩展，只提供小号（`systemSmall`，即 2×2 格）一种尺寸，在小组件库里叫「快速拍摄」。内容是静态的，不读应用里的数据。样式沿用 R-11 的卡片：`square.grid.2x2` 图标（强调色）加「快速拍摄」，整块是一个点击目标。
2. **点击。** 小组件用 `widgetURL` 打开约定的链接 `shotlist://quick-shoot`；应用注册 URL scheme `shotlist`，收到这条链接：切到「分镜」标签，等界面落位后走与卡片同一个 `quickShoot()`（新建空镜头并直接进相机，给一次轻触感）。链接是一次性的：处理完不留状态，之后正常打开应用不会再弹相机。
3. **冷启动与后台都成立。** 应用没在运行时点小组件，启动后落到分镜页并开相机；应用在后台（停在任意标签）时点，回到前台后切到分镜页并开相机。
4. **界面上已有弹层时。** 分镜页自己开着的镜头面板、模板页、快速拍摄卡片先收起（镜头面板与模板都是自动保存，收起不丢已写的内容），等界面空下来再开相机。其余弹层——相机、播放页、选片、删除或清空的确认、改名弹窗等——不打断：不新建镜头，也不弹第二个相机。等界面空下来最多等约 2 秒，超时就放弃这次请求。
5. **存储不可用时。** 读盘失败的整页错误状态下，收到链接什么也不做（`store.addShot()` 本来就返回 `nil`）。
6. **无摄像头 / 无权限时。** 走 R-11 已有的相机不可用页与权限说明页：可以「导入」，取消则撤销空镜头。

**范围：** 新增 `ShotListWidget` 小组件扩展 target（project.yml 与生成的 xcodeproj）；App 侧注册 URL scheme、`RootTabView` 收链接并切标签、`ShotListView` 触发 `quickShoot()`；应用与小组件共用一个定义链接的文件。

**推断（未经用户确认）：**

- 「小号的组件」按 iOS 的小号（`systemSmall`）解读，正好是主屏 2×2 格。
- 「点击直接进入快速拍摄」按 R-11 点卡片后的效果解读：新建空镜头并直接进相机，不经过镜头面板。
- 小组件画面沿用卡片的宫格图标与「快速拍摄」，不显示镜头数、影片名等动态内容；想要动态内容需另立需求（会引入 App Group 与时间线刷新）。
- 分镜页以外的标签页收到链接时，切到分镜页再开拍（而不是在原标签页里开）。

**明确不做：**

- 不做中号、大号，也不做锁屏、待机、控制中心组件；不做长按主屏图标的快捷操作（Quick Actions）。
- 不做动态内容，不引入 App Group，不做时间线刷新。
- 不改 R-11 的卡片、相机页、导入与收尾流程，不新增数据字段。

**对其他功能的影响：**

- **新增 target 与签名。** 小组件包标识 `com.max.ShotList.Widget`，团队与自动签名同应用；随应用一起安装、卸载。真机首次要通过 Xcode 运行一次 ShotList 才会带上小组件。
- **自定义 URL scheme。** 其他程序打开 `shotlist://quick-shoot` 也能让应用进入快速拍摄（新建一个空镜头并弹相机，取消会撤销）。链接不带参数、不读写数据，可以接受。
- **与 R-11。** 复用 `quickShoot()` 与它的收尾（`ShotFlowModifier`），这两处不改。
- **标签记忆。** 收到链接会把标签切到「分镜」，由 `SceneStorage` 记住，下次启动仍停在分镜页。

**定级依据：** 定为 P2（用户未指定级别，按规则判定，如需上调请说明）。已有绕行方式（打开应用 → 分镜页 → 长按加号 → 点卡片），不阻断从拍摄到导出的主路径；属于入口效率的增强。

**验收方法**

1. 前置环境：模拟器与真机各安装 Debug 构建（含小组件）；准备一部含 3 个镜头的影片；模拟器没有摄像头，只能验证到「相机不可用页」以及经「导入」落到描述页，录制与点「使用」要真机。
2. 主屏长按空白处 → 编辑 → 添加小组件 → 搜「分镜助手」：有一个「快速拍摄」，只有小号一种尺寸；添加到主屏：占 2×2 格，画面是 2×2 宫格图标加「快速拍摄」。
3. 杀掉应用后点小组件：应用启动，停在「分镜」标签，出现相机页（真机为取景，模拟器为「相机不可用」）；末尾多出一个空镜头（编号 4）；期间没有镜头面板弹出。
4. 应用在后台、停在「历史」或「导出」标签时点小组件：回到应用后切到「分镜」标签，同上进相机。
5. 应用在后台、开着某个镜头的面板时点小组件（面板里已写了字，键盘还开着）：面板收起，随后进相机；回来后那个镜头里写的字都在。
6. 应用在后台、相机页开着时点小组件：回到原来的相机页；镜头数不变，不出现第二个相机。
7. 相机点取消（模拟器为「相机不可用」页的取消）：回到分镜页，空镜头撤销，镜头数回到 3、没有面板弹出。点「导入」选一段视频：落到这个镜头的描述页、光标在内容框里。真机：录一段点「使用」，落到描述页。
8. 收尾之后正常从图标打开应用：不会再自己弹相机。
9. 失败判据：点小组件后停在启动页或分镜页、相机没弹出；先弹出镜头面板；小组件库里出现小号以外的尺寸；相机开着时被替换成新相机，或多出没人要的空镜头；收起镜头面板后丢了刚写的字；之后正常打开应用又弹出相机；点了小组件画面被卡在半路（外观变深色、页面不动）。

**实现状态：** 已实现，待真机验收

**实现说明：**

- **小组件：** 新 target `ShotListWidget`（`app-extension`，包标识 `com.max.ShotList.Widget`，作为 ShotList 的依赖随应用嵌入）。`StaticConfiguration` + `TimelineProvider`（只放一条、`policy: .never`），`supportedFamilies([.systemSmall])`；画面是 `square.grid.2x2`（强调色，`widgetAccentable`）加「快速拍摄」，`containerBackground(.fill.tertiary)`。强调色资源单独放一份（取值与应用相同）。小组件 target 的默认隔离设为 `nonisolated`：WidgetKit 的协议要求是非隔离的，应用 target 的默认是主协程。
- **链接：** `QuickShootLink`（scheme `shotlist`、host `quick-shoot`）同时编入两个 target，小组件 `widgetURL(QuickShootLink.url)`，应用的 Info.plist 注册 URL scheme。
- **收链接：** `RootTabView.onOpenURL` 把标签切到「分镜」并置位 `quickShootRequest`（`@State`，以 Binding 传给 `ShotListView`）。`ShotListView` 用 `onChange(of:initial:)` 收下并立刻清零；`initial: true` 是为「这一页刚创建」——`TabView` 懒创建页面，应用停在历史 / 导出标签时收到链接就是这种情形。
- **开拍前的处理：** `quickShootFromWidget()` 先收起 `sheet`（镜头面板）、`isEditingTemplate`（模板页）、`isShowingQuickCard`（卡片），等 400 毫秒（冷启动的转场与弹层收起，同卡片收起后再开相机），再用 `ModalPresentation.waitUntilIdle()` 最多等 2 秒——沿视图控制器树看有没有谁在呈现别的控制器（sheet、全屏页、弹窗、popover、系统选片都算），空了才调用原有的 `quickShoot()`，否则放弃这次请求。不在 SwiftUI 里逐个判断，是因为弹层状态分散在各页（分镜页的确认弹窗，`ShotFlowModifier` 的相机 / 选片 / 导入错误，历史页自己的一套），漏掉一个就会让相机在别的弹层上呈现被系统丢掉、`cover` 卡住（R-11 踩过）。
- **取舍：** 确认弹窗、改名弹窗开着时点小组件，等不到界面空下来就放弃，不代用户点「取消」；相机、播放页开着时同样不切换。
