### P2-16 · 导出过程中素材缺失会重新编号，片段序号与界面不一致

**验证状态：** 代码级确认；需受控时序复现

**代码位置：** ShotList/Support/ExportPackageBuilder.swift · build / available.enumerated

**问题详情**

界面按 `shot.clips` 的位置显示「第 N 条」，导出却先过滤磁盘上不存在的文件，再重新从 1 编号。正常前台校正已缩小触发范围，但导出取得快照后文件消失仍会触发，导致文件名、CSV 和指南的片段号与原界面不一致。

**复现方法**

1. 准备一个含三条片段的镜头，记录界面的第 1、2、3 条及对应文件。
2. 在隔离测试中先取得 shots 快照，再删除第 1 条文件；不调用 refreshStorageStats。
3. 用该快照调用 ExportPackageBuilder.build。
4. 检查导出文件名及 CSV：原第 2 条被标成第 1 条，原第 3 条被标成第 2 条。

### P2-17 · 导出缺少空间预检，空间不足时仅显示系统错误

**验证状态：** 代码级确认；低空间场景待验证

**代码位置：** ShotList/Support/ExportPackageBuilder.swift · build / zip

**问题详情**

导出先复制素材，再生成和复制压缩包，需要额外临时空间；旧导出包可能也仍存在。流程没有检查可用空间，直到复制或打包失败才显示系统错误，没有说明空间不足及可采取的措施。实际峰值取决于复制和压缩行为，不能固定按素材大小估算。

**复现方法**

1. 在专用测试设备或受限测试卷中准备较大素材，使剩余空间不足以完成导出。
2. 点击「生成导出包」。
3. 检查是否在复制/打包阶段才失败，且提示仅包含系统错误，没有明确的空间不足说明。

### P2-18 · 素材变化后旧导出包仍可分享，未标记过期

**验证状态：** 代码级确认

**代码位置：** ShotList/Views/ExportView.swift · package / build / resultSection

### P2-20 · 缩略图失效后在途任务仍回写旧图并清掉新任务

**验证状态：** 代码级确认；需受控时序复现

**代码位置：** ShotList/Support/Haptics.swift · ThumbnailLoader.thumbnail / invalidate / removeAll

**问题详情**

`invalidate` 只清除缓存和在途任务表，不阻止旧解码任务完成。旧任务恢复后仍无条件写入缓存，并把同路径的 inFlight 项清空；如果该路径已经发起新任务，新任务记录也会被误删。视图的取消检查无法保护加载器缓存。

**复现方法**

1. 在隔离测试中启动路径 A 的缩略图解码，用可控等待暂停结果返回。
2. 调用 invalidate(for: A)，将 A 替换为另一段视频，再发起同路径的新请求。
3. 让旧任务先完成、新任务继续等待。
4. 检查缓存及 inFlight：旧图被写回，新任务记录被清掉；后续请求可能读到旧图或重复解码。

### P2-25 · 前一次导入完成会清空后一次相册选择的目标

**验证状态：** 代码级确认；PhotosPicker 交互待验证

**代码位置：** ShotList/Views/ShotFlowModifier.swift · pickerItem.onChange / drainQueue / importMovie

**问题详情**

多个导入共用 `pickerTarget` 和 `isImporting`。前一个任务结束时无条件清空目标并隐藏进度，可能覆盖后一个操作的状态；随后选择的视频因 target 为 nil 被直接忽略，也没有错误提示。

**复现方法**

1. 为镜头 A 开始导入，通过可控延迟让导入保持等待。
2. 导入未结束时，为镜头 B 打开相册选择器，暂不选择视频。
3. 让 A 完成，再在选择器中选择 B 的视频。
4. 检查 B：视频没有导入，因为 A 的 defer 已将 pickerTarget 清空。若两个任务已启动，先完成的一次还会提前隐藏进度。

### P2-26 · 导入目标被删除后仍返回成功，并残留临时文件

**验证状态：** 隔离存储实测

**代码位置：** ShotList/Models/ShotStore.swift · addClip；ShotList/Views/ShotFlowModifier.swift · importMovie

**问题详情**

异步导入结束时目标镜头可能已被删除。`addClip` 找不到目标便直接 return，不抛错，调用方仍执行成功反馈。素材没有加入任何镜头，中转文件也没有在本次操作结束时清理。

3. 观察方法无错误返回，但 clips=0、source_exists=true。
4. 对应界面路径是：视频导入等待期间删除目标镜头或清空全部分镜，之后等待导入完成。

### P2-28 · 同时间戳片段交换镜头顺序后，文件名编号错位

**验证状态：** 隔离存储实测

**代码位置：** ShotList/Models/ShotStore.swift · normalize / syncClipFileNames

**问题详情**

不同镜头可以拥有相同时间戳 token。交换镜头顺序时，两个文件的目标名互相占用，重命名逻辑因目标存在全部跳过。内存编号已更新，后续 normalize 不会再尝试改名，文件名与镜头编号长期不一致。

**复现方法**

1. 在隔离目录准备两个镜头，分别引用镜头01_20260915_120000.mov 和镜头02_20260915_120000.mov。
2. 加载 ShotStore，交换两个镜头的顺序。
3. 检查记录：镜头 1 仍引用镜头02_…，镜头 2 仍引用镜头01_…。
4. 重新加载，确认错位仍存在；原文件内容没有被覆盖。

### P2-29 · 删除失败仍移除记录，孤儿清理虚报成功数量

**验证状态：** 隔离存储实测

**代码位置：** ShotList/Models/ShotStore.swift · removeClip / removeAllClips / removeFile / removeOrphanFiles

**问题详情**

3. 检查结果：clips=0、orphans=1，文件没有删除但已失去引用。
4. 继续调用 removeOrphanFiles：返回 1，实际剩余孤儿文件仍为 1。

**修复状态：** 已修复

**修复说明：** 删除延迟追加描述的临时探针，取消后不再抢焦点，未编辑草稿不触发首尾空白裁剪。
