1. **14 个镜头全部入选，没有一条被丢掉**——「去除废片」不是丢镜头，而是**在每条素材内部掐出 0.5–2.2 秒**。

## 二、问题一：App 里要预设什么

现状：这些意图全部塞在 `Shot.note` 一段自由文本里，例如

```
早上起床称体重的画面；字幕 热量缺口2000大卡，这个是挂在右上角的字幕
```

目标：拆成**三层结构**——影片级风格、镜头级覆盖、导出侧机器可读规格。

### 2.1 影片级 `FilmStyle`（挂在 `Film` 上）

一次设定、整部影片共用，决定「怎么剪」与「哪些样式是全局的」。**已实现的字段**
（见 `ShotList/Models/FilmStyle.swift`）：

| 字段 | 说明 | 默认值 |
|---|---|---|
| `canvas` | 画幅：`vertical4K` / `vertical1080` | `vertical4K`（2160×3840） |
| `frameRate` | 帧率：`fps30` / `fps60` | `fps30` |
| `pacing.targetMinDuration` / `targetMaxDuration` | 成片总时长区间（秒），不含片尾卡 | 18 / 22 |
| `pacing.shotMinDuration` / `shotMaxDuration` | 单镜时长区间（秒） | 0.6 / 2.5 |
| `typography.family` | 字体族：黑体 / 圆体 / 宋体 | 黑体 |
| `typography.weight` | 字重：常规 / 中等 / 粗体 / 特粗 | 特粗 |
| `typography.sizeRatio` | 字号占屏高比例 | 0.044 |
| `typography.strokeRatio` | 描边宽占屏高比例 | 0.003 |
| `typography.colorHex` / `strokeColorHex` | 文字色 / 描边色 | #FFFFFF / #000000 |
| `badge` | 常驻角标：开关 / 位置 / 距顶比例 / 最多行数 / 文案来源 / 模板 | 开 · topCenter · 0.042 · 1 行 · shotText · `热量缺口：{value}千卡` |
| `caption` | 分镜字幕：同上六项 | 开 · lowerThird · 0.709 · 2 行 · shotText · 空 |
| `tailCard.overlay` | 片尾卡的文字（位置 / 行数 / 文案来源 / 文案） | 开 · center · 2 行 · fixed · `今日热量缺口：\n{value}千卡` |
| `tailCard.duration` | 片尾卡时长（秒） | 0.7 |
| `tailCard.backgroundColorHex` | 片尾卡底色 | #000000 |
| `audio.mode` | `original` 保留原声 / `silent` 静音 | original |
| `audio.originalGain` | 原声音量（0–1） | 1.0 |

三条设计取舍：

- **位置一律写两个值**：`anchor` 是给人看的位置名，`offsetYRatio`（文字块中心距屏幕
  顶部的比例）才是规格里的权威数值。只留名字没法微调，只留数字没法读。
- **文字样式只有一套**，不做逐图层覆盖：实测成片里角标、字幕、片尾卡的字号与描边
  完全一致，再开一层覆盖只会多出一组没人用的旋钮。
- **没有再设一个「照抄 / 精炼改写」开关**：字幕文案由用户自己在分镜描述里写，
  指南那条「不要自行扩写或改写语义」不再与成片做法冲突（见第四节第 1 条）。

### 2.2 第二层：镜头级 `ShotOverlay`（挂在 `Shot` 上）

> **这一层本次不做。** 字幕文案与角标数值属于「内容」，用户自己在分镜描述里写，
> 不改数据结构。这一节留在这里是因为下面那个 `keep` 字段是**下一步**最该补的东西
> ——它是「去除废片」唯一缺的信息（见 1.4 与 4.3）。等到要动它是单独一个 feature。

`note` 只留画面描述，其余拆成独立字段：

| 字段 | 说明 | 示例 |
|---|---|---|
| `caption` | 屏幕字幕文案（含 `\n` 显式断行） | `感觉没练到位加一组二头弯举\n15KG * 2 * 8` |
| `badgeValue` | 该镜角标数值（**直接填最终值，不要填增量**） | `2318` |
| `badgeSegment` | 同值连续段，只在段首镜头填一次，后续镜头沿用 | 镜头 11/12/13 共用 `1168` |
| `keep` | 在源素材里的保留区间，单位秒 | `[12.4, 14.3]` |
| `speed` | 倍速 | `1.0` |
| `exclude` | 拍了但不进成片 | `false` |
| `inTailCard` | 片尾卡独立于镜头，不占镜头号 | — |

`keep` 有三种填法，按可靠度排序：

1. **精确区间**（`keep`）：在 App 里拖动选好入点出点。最可靠，AI 只负责切。
2. **锚点 + 时长**（`keepFrom` + `keepDuration`，如 `["middle", 1.5]`）：不精确但比猜强。
3. **留空**：AI 只能按启发式挑（见 3.3）。**这是当前唯一的情况，也是不确定性的全部来源。**

### 2.3 导出侧的 `剪辑规格.json`

导出包里放一个**机器可读**的 sidecar，不要只靠 markdown 表格让 AI 解析。实际产出长这样
（默认风格，`ShotList/Support/ExportPackageBuilder.swift` 的 `writeStyleSpec`）：

```json
{
  "audio": { "mode": "original", "originalGain": 1 },
  "canvas": {
    "fps": 30, "height": 3840, "orientation": "portrait", "width": 2160,
    "sourceNote": "素材常见 rotation=-90，编码尺寸报横屏但实际为竖屏；判断方向请看本字段，不要用 ffprobe 的 width/height"
  },
  "film": { "exportedAt": "2026-09-16T15:26:00Z", "title": "减脂日记" },
  "overlays": {
    "badge": {
      "anchor": "topCenter", "contentSource": "shotText", "enabled": true,
      "horizontalAlignment": "center", "maxLines": 1, "offsetYRatio": 0.042,
      "text": "热量缺口：{value}千卡"
    },
    "caption": {
      "anchor": "lowerThird", "contentSource": "shotText", "enabled": true,
      "horizontalAlignment": "center", "maxLines": 2, "offsetYRatio": 0.709, "text": ""
    },
    "tailCard": {
      "anchor": "center", "backgroundColor": "#000000", "contentSource": "fixed",
      "duration": 0.7, "enabled": true, "horizontalAlignment": "center",
      "maxLines": 2, "offsetYRatio": 0.5, "text": "今日热量缺口：\n{value}千卡"
    }
  },
  "pacing": { "shotDuration": [0.6, 2.5], "tailCardDuration": 0.7, "targetDuration": [18, 22] },
  "specVersion": 1,
  "typography": {
    "color": "#FFFFFF", "family": "heiti",
    "fontFileHint": "/System/Library/Fonts/Hiragino Sans GB.ttc",
    "sizeRatio": 0.044, "strokeColor": "#000000", "strokeRatio": 0.003, "weight": "heavy"
  }
}
```

要留意的地方：

- **没有 `shots` 数组**。逐镜的字幕文案与角标数值是内容，仍在各镜的分镜描述里，
  由「分镜文字内容指南.md」提供——规格文件只管影片级那一层。
- **只有比例，没有像素**。位置看 `offsetYRatio`（文字块中心距屏幕顶部），字号看
  `sizeRatio`，描边看 `strokeRatio`，三者都相对屏高，导 4K 与导 1080p 同一个观感。
- **`anchor` 与 `offsetYRatio` 同时给出**：前者是给人读的位置名，后者才是权威数值。
- **数值是原样的 `Double`**：`JSONSerialization` 会写成 `0.043999999999999997`
  这种 17 位有效数字。值本身没错（就是 0.044），别当异常；想读百分数看指南那一节。
- **关掉的图层仍然在文件里**：`enabled: false`，且片尾卡的 `duration` 与
  `pacing.tailCardDuration` 一起变成 `0`，剪辑侧不必再猜「是不是还要留黑屏」。
- 文件按 `sortedKeys` 输出，键顺序固定，diff 才有意义。

同时把 `分镜文字内容指南.md` 补了一节（沿用现有编号，接在「三、镜头清单」之后）：

- **「四、成片规格」**：同一份参数的散文版，人也能读；末尾明确写「冲突时以 JSON 为准」。
- 原来的「四、汇总」顺延为**「五、汇总」**。

## 三、问题二：怎么指引 WorkBuddy

### 3.1 固定指令模板

把下面这段存成常驻提示词，每次只换目录：

```
读取分镜导出包 <目录>，按以下两阶段做初剪。

阶段一 · 只出方案，不渲染：
1. 读 剪辑规格.json（影片级硬参数）与 分镜文字内容指南.md（逐镜内容，
   其中「四、成片规格」是同一份参数的散文版）。
   两者冲突时以 剪辑规格.json 为准。
   画幅、帧率、总时长区间、单镜区间、图层位置、字号描边、音轨一律取自 JSON，
   不要用你熟悉的那套默认值代替。
2. 输出时间线表：编号 | 源文件 | 保留区间 | 镜头时长 | 角标 | 屏幕字幕。
3. 自校核：Σ 镜头时长 + pacing.tailCardDuration ∈ pacing.targetDuration；
   每镜 ∈ pacing.shotDuration；字幕每行 ≤ 24 字、≤ caption.maxLines 行。
4. 停在这里，等我说「通过」再继续。

阶段二 · 渲染：
5. 输出画幅与帧率取自 canvas.width / canvas.height / canvas.fps。
   注意源素材 rotation=-90，必须按 canvas.orientation 摆放，
   不要用 ffprobe 的 width/height 判方向。
6. 文字一律用 Pillow 预渲染成透明 PNG 再 overlay：
   字号 = typography.sizeRatio × 画面高，描边 = typography.strokeRatio × 画面高；
   渲染前先量一遍文本宽度，超宽按该图层的 maxLines 断行。
   位置用 overlays.*.offsetYRatio（文字块**中心**距屏幕顶部）。
7. 片尾卡按 overlays.tailCard：黑底、文字垂直居中，时长 pacing.tailCardDuration；
   为 0 就不要加这一段。
8. 渲完抽 14 帧贴成对比图给我，标出每帧对应的时间点。

硬性禁止：
- 不推算角标数值：数值按我写在分镜描述里的原文来，推不出来就问我，别自己凑。
- 不按文件名/体积/修改时间重排镜头顺序，顺序就是编号顺序。
- 不跳过任何已拍镜头；只跳过指南里标注「未拍摄」的。
- 字幕文案照抄分镜描述，不扩写、不改写、不加自己的总结。
  （要更凝练的话我会自己把字幕写成成品文案再导出，轮不到你改。）
```

> 上面这条模板只用到**已经落地**的字段。`badgeValue` / `exclude` / `caption` 这些
> 逐镜字段属于第 2.2 节，还没实现——所以角标数值和字幕目前都只能从分镜描述里读。
> 等 2.2 做出来之后这条模板要同步改成直接读逐镜字段。

### 3.2 为什么必须分两阶段

时间线表的成本是几十秒，渲染的成本是几分钟到十几分钟。先看表能一次性发现「某镜时长超了」
「某条字幕溢出」「角标跳变不合理」，比渲完再回炉省一个数量级。

### 3.3 没有 `keep` 时，让 AI 怎么挑

明确写下优先级，别让它自由发挥：

1. 素材 ≤ 3 s：整条用，头尾各留 0.2 s 余量避免黑帧。
2. 素材 > 3 s：取**动作中段**——用 `ffmpeg -vf "select='gt(scene,0.15)'"` 找出画面变化最密集的区间，
   从中截取目标时长。
3. 全程无变化（静态菜品、屏幕录制）：取**第 40 % 位置**起截取，避开开头的手部晃动与结尾的收手机。
4. 无论如何不用素材的**第 0–0.5 s 与最后 0.5 s**。

### 3.4 时长怎么分配

`Σ 镜头时长 = pacing.targetDuration 中值 − pacing.tailCardDuration`，再按下面权重分：

- 基线：每镜取下限 `pacing.shotDuration[0]`。
- 富余时间按「素材长度」加权分配，单镜不超过 `pacing.shotDuration[1]`。
- 文案是两行的镜头（如镜头 9）额外 +0.3 s，避免字幕来不及读。

基线 19.13 s ≈ (18+22)/2 = 20 s − 0.7 s 片尾卡 − 少量收尾余量，与实测吻合。

### 3.5 字体与文字图层

- 本机 ffmpeg 无 `drawtext` / `libass`，**必须走 Pillow 预渲染透明 PNG + overlay**。
- 字体取 `typography.fontFileHint`（默认 `/System/Library/Fonts/Hiragino Sans GB.ttc`，
  `.ttc` 用 `index=0` 常规 / `index=1` 粗体，对应 `typography.weight`）；
  换成用户配的圆体/宋体时，这个字段会跟着变，别写死黑体。
- 字号与描边一律 `typography.sizeRatio` / `strokeRatio` × 画面高，**不要按像素点写死**。
- 描边是**白色文字 + 黑色外描边**，不是阴影、不是半透明底条。这一点在明亮画面（健身房、瓷砖地面）上是可读性的全部来源。
- 片尾卡是纯黑底 + 白字，不叠原画面。

## 四、实测发现的 6 个坑

| # | 问题 | 证据 | 后果 |
|---|---|---|---|
| 1 | ~~指南写死「不要自行扩写或改写语义」，成片却是精炼改写~~ **已解决** | 「早上起床称体重的画面」→「今日体重114.1KG」；「累死」→「微死了」 | 字幕文案由用户自己写（见 2.2），指南那条规则不再与成片做法冲突 |
| 2 | `note` 里写「挂在右上角」，成片实际是**顶部居中** | 1.2 节实测：水平居中偏差 ≤ 2 px | 位置类要求写自然语言必然漂移，必须枚举化 |
| 3 | 长素材没有任何入出点信息 | 04/05/06/10 共 178.5 s，成片只用 6.22 s（3.5 %） | AI 只能猜哪 1–2 秒是好镜头，这是最大不确定性源 |
| 4 | 角标数值无法由摄入/消耗推算 | 实测 2000→1500→1758→2318→1168→768；镜头 06 的 note 写「加300大卡」，实际是 1758（1500+258） | 让 AI 做算术必错，数值必须人工回填最终值 |
| 5 | 素材方向会被误判 | 全部素材 `rotation=-90`，ffprobe 报 3840×2160，实为竖屏 2160×3840；而 03/09/11 是原生竖屏 | 按编码尺寸判方向 → 输出横屏全废 |
| 6 | 字幕会溢出单行 | 单行上限约 46 % 屏宽；「感觉没练到位加一组二头弯举」必然折行 | 自动折行可能断成「…二头弯」/「举」，需显式 `\n` |
