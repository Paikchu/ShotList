两层各管一件事，分界线是**怎么剪 vs 写什么字**：

- **影片级**（`Film.stylePrompt` → `剪辑风格.md`）是一段自然语言，说**怎么剪**：
  画幅、节奏、时长区间、图层贴在哪儿、文字什么样式、要不要音乐。整片一套。
- **镜头级**（`Shot.caption` / `Shot.badgeText` → 指南与 CSV）写**这一镜显示什么字**。
  逐镜一条。

这条线让「指南写死不要自行扩写或改写语义」从一句期望变成可执行的要求：
要上屏的字已经由用户写好了，剪辑侧没有需要猜的地方。

一个镜头的文字因此分成三样，**互不冒充**：

| 字段 | 是什么 | 谁用 |
|---|---|---|
| `note` | 画面描述：这一镜拍什么 | 剪辑侧挑素材、定起止、调色的依据 |
| `caption` | 屏幕字幕：成片上显示的那句话 | **原样上屏**，不改写 |
| `badgeText` | 角标文字：常驻角标上要显示的整段字 | **原样上屏** |

在这三样分开之前，字幕与角标只能塞在 `note` 里，剪辑侧无法判断一句话是
「画面的说明」还是「要显示的字」——只能靠改写去猜，那就必然和「不要改写」打架。

## 二、问题一：App 里要预设什么

现状：这些意图全部塞在 `Shot.note` 一段自由文本里，例如

```
早上起床称体重的画面；字幕 热量缺口2000大卡，这个是挂在右上角的字幕
```

目标：拆成**三层结构**——影片级风格描述、镜头级文字、导出侧交给剪辑工具的说明。

### 2.1 影片级 `Film.stylePrompt`（一段描述，不是一组选项）

一次写好、整部影片共用，说清「**怎么剪**」。**已实现为一个字符串字段**，
编辑界面就是「剪辑风格」页里的一个多行输入框（`FilmStyleView`）：

| 项 | 说明 | 示例（`FilmStylePrompt.placeholder`） |
|---|---|---|
| 字段 | `Film.stylePrompt: String` | — |
| 落盘 | `剪辑风格.md`，正文**一字不改** | — |
| 空值 | 不产出该文件，指南改口说「按常规处理」 | — |
| 输入框为空时 | 显示灰色**占位示例**（不是已填内容） | `竖屏 1080×1920、30fps，总长 20 秒左右，单镜 0.5–2.5 秒，快切不拖沓。…` |
| 输入框下方 | 「可以写这些」7 条要点，只是提示、不限制写法 | 画幅与帧率 / 时长与节奏 / 音轨 / 图层位置与行数 / 文字样式 / 片尾卡 / 其他偏好 |

三条设计取舍：

- **不再是枚举 + 滑块**。以前这一层是 `FilmStyle`（画幅、帧率、节奏、字号、描边、
  颜色、三个图层各自的 `anchor` / `offsetYRatio` / `maxLines` / 模板、音轨……）。
  消费它的本来就是**能读自然语言的剪辑工具**，而旋钮只能表达「已经想到的那些」：
  「快切不拖沓」「别加音乐」「转场别花」这些真正想说的话没有对应控件。
  想到第十一种风格时，用户只能等应用加旋钮。
- **没有丢掉已经调好的旧配置**。旧数据里的 `Film.style` 由 `LegacyFilmStyle`
  一次性翻译成描述（`0.044` → `4.4%`，`topCenter` → `顶部居中`，`heiti` → `黑体`），
  写进 `stylePrompt` 之后旧键不再落盘。这件事有 13 个测试钉着
  （`ShotListTests/FilmStylePromptTests.swift`）。
- **位置与字号仍然给数值**，只是换成写在句子里（「文字块中心距屏顶约 2%」）——
  位置类要求写纯自然语言必然漂移（第四节第 2 条），数值是防漂移的那一半。

### 2.2 第二层：镜头级的 `caption` / `badgeText`（挂在 `Shot` 上）

**已经实现的内容部分。** 画面描述留在 `note`，屏幕上的字拆成两个独立字段：

| 字段 | 说明 | 示例 |
|---|---|---|
| `note` | 画面描述（原来就在） | `早上起床称体重的画面` |
| `caption` | 屏幕字幕文案，含 `\n` 表示显式断行 | `今日体重114.1KG` |
| `badgeText` | 角标要显示的**整段文字**（不是数值，也不走模板） | `热量缺口：1758千卡` |

写入点在镜头面板（`ClipOptionsSheet`）的「屏幕文字」一节，与描述一样走
400ms 草稿落盘，两行输入框各带常驻标签。留空的含义是**这一镜没有这一项**，
不是「沿用上一镜」——连续几镜共用同一段字时，面板上有一个「沿用上一镜」
按钮把值**显式抄过来**。

> 为什么不做「留空即沿用」：那样「留空」会有两个含义（沿用 / 不出角标），
> 「不想出角标」这件事就没法表达。显式抄一次，两个含义各归其位。

> 为什么角标从「数值 + 全局模板」改成「整段文字」：模板属于**影片级**，
> 而 `{value}` 的代入是**逐镜**的——两层各自要一半，剪辑侧就得自己做一次字符串拼接。
> 改成让各镜写完整文字之后，指南给出的那一行就是**最终要显示的字**，
> 剪辑侧没有任何推算或拼装的余地。旧数据的 `badgeValue: "1758"` 会按
> 「数值即文字」直接读成 `badgeText`，不会丢。

#### 还没做：`keep` / `speed` / `exclude`

下面这一组是**裁剪**层面的信息，与「写什么字」是两件事，所以没有跟着一起做：

| 字段 | 说明 | 示例 |
|---|---|---|
| `keep` | 在源素材里的保留区间，单位秒 | `[12.4, 14.3]` |
| `keepFrom` + `keepDuration` | 锚点 + 时长 | `["middle", 1.5]` |
| `speed` | 倍速 | `1.0` |
| `exclude` | 拍了但不进成片 | `false` |

`keep` 有三种填法，按可靠度排序：

1. **精确区间**（`keep`）：在 App 里拖动选好入点出点。最可靠，AI 只负责切。
2. **锚点 + 时长**（`keepFrom` + `keepDuration`，如 `["middle", 1.5]`）：不精确但比猜强。
3. **留空**：AI 只能按启发式挑（见 3.3）。**这是当前唯一的情况，也是不确定性的全部来源。**

做 `keep` 需要一套拖动入点出点的界面，是单独一个 feature；`caption` / `badgeText`
只需要两个输入框，所以先做了它。字幕与描述混在一起是**每次都会误导 AI** 的问题，
`keep` 缺失只是**精度不够**——前者优先级更高。

### 2.3 导出侧的 `剪辑风格.md`

导出包里放一段**自然语言**的 sidecar，不再放机器可读的固定字段 JSON。
实际产出（`ShotList/Support/ExportPackageBuilder.swift` 的 `writeStylePrompt`）：

```markdown
# 剪辑风格 · 夏日vlog

下面是这部影片的剪辑要求，**照它剪**。写到哪几条就按哪几条来，
没提到的部分按常规处理；本片的分镜内容见同目录「分镜文字内容指南.md」。

---

竖屏 1080×1920、30fps，总长 20 秒左右，单镜 0.5–2.5 秒，快切不拖沓。
保留现场原声，不加解说、不加背景音乐。
顶部居中一行角标（不透明黑底条），底部居中两行以内字幕，都是白色粗体加黑描边，字高约占屏高 4.4%。
结尾 0.7 秒黑底卡，居中写一句收尾。
```

要留意的地方：

- **删掉了 `剪辑规格.json`**。理由见 2.1 的取舍：固定字段既加不完，也表达不了
  字段之外的偏好。留一个空壳反而会让剪辑侧以为参数在别处、不知道该信哪一份。
- **正文一字不改**。只有文件头那三行是应用加的，作用是说明「这是什么、跟谁配合」；
  用户写的就是要执行的。
- **描述为空时整个文件不产出**。一个空文件会让剪辑侧以为「有要求但没写清」，
  而事实是这条片子没有特别要求。
- **判「有没有」与「写不写」用的是同一个值**（都取裁掉首尾空白之后的字符串）。
  只在空白上分叉，就会出现「指南说有那个文件、包里却没有」这种自相矛盾。

同时 `分镜文字内容指南.md` 补了一节，接在开头之后、编号在前的「剪辑风格看哪」：

- 写明**画幅、节奏、时长、图层位置、文字样式、音轨这些影片级要求不在本文件里**，
  在同目录的 `剪辑风格.md`。
- 分两版：有那个文件时写「本片有那份文件，开始前先读它。」；
  没有时写「本片没有那份文件，说明用户没有特别要求，这几项由你按常规判断。」
  ——只说「照它执行」会让剪辑侧去找一个不存在的文件。
- 逐镜的「屏幕字幕 / 角标」两行现在**无条件列出**（以前按图层开关决定列不列）：
  开关只写在那段描述里，指南这边没有依据判断「整片出不出这一层」，
  所以一律给出行、由 `—` 表示这一镜没有。

## 三、问题二：怎么指引 WorkBuddy

### 3.1 固定指令模板

把下面这段存成常驻提示词，每次只换目录：

```
读取分镜导出包 <目录>，按以下两阶段做初剪。

阶段一 · 只出方案，不渲染：
1. 先读 剪辑风格.md（影片级：这部片子该怎么剪，用户自己写的一段话），
   再读 分镜文字内容指南.md（逐镜内容）。指南开头的「剪辑风格看哪」一节会
   说明本片有没有那份文件：
   - 有：它写的照它执行，画幅、节奏、时长区间、图层位置、文字样式、音轨
     一律按它，不要用你熟悉的那套默认值代替。
   - 没有：说明用户没有特别要求，这几项按常规判断，别去猜一个不存在的文件。
2. 逐镜读**三样互不顶替的文字**：分镜描述（拍什么，你挑画面/定起止的依据）、
   屏幕字幕（成片上显示的那句话）、角标（要常驻显示的那段字）。
   指南里 `反引号` 包起来的是要原样显示的字，`—` 是这一镜没有这一项。
3. 输出时间线表：编号 | 源文件 | 保留区间 | 镜头时长 | 角标 | 屏幕字幕。
4. 自校核：Σ 镜头时长 + 片尾卡时长 ∈ 风格描述里写的总时长区间；
   每镜 ∈ 单镜区间；字幕每行 ≤ 24 字、不超过风格描述里写的行数上限。
5. 停在这里，等我说「通过」再继续。

阶段二 · 渲染：
6. 输出画幅与帧率按 剪辑风格.md 写的来。
   注意源素材 rotation=-90，必须按竖屏摆放，
   不要用 ffprobe 的 width/height 判方向。
7. 文字一律用 Pillow 预渲染成透明 PNG 再 overlay：
   字号与描边按风格描述里写的比例 × 画面高；
   渲染前先量一遍文本宽度，超宽按那个图层写明的行数上限断行。
   位置用描述里的比例（文字块**中心**距屏幕顶部）。
8. 片尾卡按描述里写的底色与时长；写成 0 或没提就不要加这一段。
9. 渲完抽 14 帧贴成对比图给我，标出每帧对应的时间点。

硬性禁止：
- 不推算、不改写角标文字：指南「角标」那一行就是最终要显示的字，照抄。
- 不按文件名/体积/修改时间重排镜头顺序，顺序就是编号顺序。
- 不跳过任何已拍镜头；只跳过指南里标注「未拍摄」的。
- 字幕照抄指南里的「屏幕字幕」，不扩写、不改写、不加自己的总结，也不拿分镜描述当字幕。
  （要更凝练的话我会自己把字幕写成成品文案再导出，轮不到你改。）
```

> 这条模板按**已经落地**的字段写：风格是一段自然语言（`剪辑风格.md`），
> 逐镜的字在 `caption` / `badgeText`（第 2.2 节）里直接给成品。
> 尚未实现的只有镜头级 `keep`——模板里没用到它，等它落地再补一行。

### 3.2 为什么必须分两阶段

时间线表的成本是几十秒，渲染的成本是几分钟到十几分钟。先看表能一次性发现「某镜时长超了」
「某条字幕溢出」「角标跳变不合理」，比渲完再回炉省一个数量级。

### 3.3 没有 `keep` 时，让 AI 怎么挑

明确写下优先级，别让它自由发挥：

1. 素材 ≤ 3 s：整条用，头尾各留 0.2 s 余量避免黑帧。
2. 素材 > 3 s：取**动作中段**——用 `ffmpeg -vf "select='gt(scene,0.15)'"` 找出画面变化最密集的区间，
   从中截取目标时长。
3. 全程无变化（静态菜品、屏幕录制）：取**第 40 % 位置**起截取，避开开头的手部晃动与结尾的收手机。
4. 无论如何不用素材的**第 0–0.5 s 与最后 0.5 s**。

### 3.4 时长怎么分配

`Σ 镜头时长 = 风格描述里写的总时长区间中值 − 片尾卡时长`，再按下面权重分：

- 基线：每镜取单镜区间下限。
- 富余时间按「素材长度」加权分配，单镜不超过单镜区间上限。
- 文案是两行的镜头（如镜头 9）额外 +0.3 s，避免字幕来不及读。

基线 19.13 s ≈ (18+22)/2 = 20 s − 0.7 s 片尾卡 − 少量收尾余量，与实测吻合。

### 3.5 字体与文字图层

- 本机 ffmpeg 无 `drawtext` / `libass`，**必须走 Pillow 预渲染透明 PNG + overlay**。
- 字体默认取 `/System/Library/Fonts/Hiragino Sans GB.ttc`（`.ttc` 用 `index=0` 常规 /
  `index=1` 粗体）；用户在风格描述里换了字体就跟着换，别写死黑体。
- 字号与描边一律按风格描述里写的**占屏高比例**算，**不要按像素点写死**。
- 描边是**白色文字 + 黑色外描边**，不是阴影、不是半透明底条。这一点在明亮画面（健身房、瓷砖地面）上是可读性的全部来源。
- 片尾卡是纯黑底 + 白字，不叠原画面。

## 四、实测发现的 6 个坑

| # | 问题 | 证据 | 后果 |
|---|---|---|---|
| 1 | ~~指南写死「不要自行扩写或改写语义」，成片却是精炼改写~~ **已解决** | 「早上起床称体重的画面」→「今日体重114.1KG」；「累死」→「微死了」 | 字幕文案由用户自己写（见 2.2），指南那条规则不再与成片做法冲突 |
| 2 | `note` 里写「挂在右上角」，成片实际是**顶部居中** | 1.2 节实测：水平居中偏差 ≤ 2 px | 位置类要求写自然语言必然漂移，必须枚举化 |
| 3 | 长素材没有任何入出点信息 | 04/05/06/10 共 178.5 s，成片只用 6.22 s（3.5 %） | AI 只能猜哪 1–2 秒是好镜头，这是最大不确定性源 |
| 4 | 角标文字无法由摄入/消耗推算 | 实测 2000→1500→1758→2318→1168→768；镜头 06 的 note 写「加300大卡」，实际是 1758（1500+258） | 让 AI 做算术必错，角标必须人工回填最终文字（现在填的就是整段字） |
| 5 | 素材方向会被误判 | 全部素材 `rotation=-90`，ffprobe 报 3840×2160，实为竖屏 2160×3840；而 03/09/11 是原生竖屏 | 按编码尺寸判方向 → 输出横屏全废 |
| 6 | 字幕会溢出单行 | 单行上限约 46 % 屏宽；「感觉没练到位加一组二头弯举」必然折行 | 自动折行可能断成「…二头弯」/「举」，需显式 `\n` |
